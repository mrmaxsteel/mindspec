# Spec 128-lifecycle-verb-state-honesty: Lifecycle verb state honesty + claim/selection (spec-127 split, part 2)

*Citation scope: all `file:line` citations in this document were resolved against the spec-128 worktree at `06273a19` (branch `spec/128-lifecycle-verb-state-honesty`, forked from `main` after spec 127's merge, PR #236 / `ae45fd7a`) on 2026-09-01, unless a citation is explicitly marked historical (e.g. an issue body's line numbers at an older base). Where an inherited citation had drifted, the refreshed line is given and the drift noted.*

## Goal

After this spec, the lifecycle verbs tell the truth about state and act deterministically on it:

- (a) `mindspec state show` and every verb's instruct tail report the phase the system is actually in — a draft spec is never reported as `idle` alongside a non-empty `activeSpec`, and success output is never indistinguishable from a no-op (#220, #245);
- (b) no verb emits a recovery hint whose execution makes state worse on a reproducible state — pinned by the deterministic plan-approve → first-claim `repair phase` regression fixture (#248), and `repair phase` itself refuses a backward lifecycle move it was not explicitly forced into;
- (c) a gate-refused `mindspec complete` converges: an immediate retry meets the *same* gate the first run failed, never a stale-SHA block manufactured by the tool's own tracker auto-commit (#186 — the real fix; spec 127 shipped only the interim mitigation of removing the destructive documented workaround);
- (d) `mindspec next`'s dirty-tree claim guard blocks only on dirt the claim operation could actually entangle, rebuilt on the settled fact that there is no in-place claim mode (#179);
- (e) bead selection is deterministic and honest: a positional bead ID resolves to exactly that bead or errors with the true reason, `--pick N` is honored with `bd ready`-consistent ordering on both the claim and `--emit-only` paths, and a failing `bd` shell-out surfaces bd's own stderr (#187, #146 remainder);
- (f) mode guidance states that implementing an externally-merged or frozen contract still requires a new spec, naming spec 127's shipped adopt path by its real invocation: `mindspec impl adopt <spec-id> --reason "<why>"` (#221).

### The live evidence, verified 2026-09-01

**#220 (mode-derivation dishonesty) reproduces at HEAD, both shapes.** From the `main` checkout: `mindspec state show` → `{"mode": "idle"}` while spec 128 is an active draft. From *inside* this spec's own worktree: `{"mode": "idle", "activeSpec": "128-lifecycle-verb-state-honesty", "specBranch": "spec/128-lifecycle-verb-state-honesty"}` — mode `idle` printed alongside a non-empty active spec, a self-contradictory output. Mechanism, pinned:

- `resolve.ResolveModeWithCache` returns `state.ModeIdle` whenever no epic exists for the spec (`internal/resolve/resolve.go:57-67` — "Returns ModeIdle if no epic exists"). A draft spec by definition has no epic (the epic is created at `spec approve`), so every draft resolves as `idle`.
- `state show` composes its output from `resolve.ResolveMode` for `Mode` but `phase.ResolveContextFromDir` only for `ActiveBead` (`cmd/mindspec/state.go:80-97`) — even though the context path *already knows better*: `ResolveContextFromDirWithCache`'s `WorktreeSpec` branch sets `Phase = state.ModeSpec` for a spec worktree without an epic (`internal/phase/derive.go:568-579`, "spec worktree without epic → spec mode"). The honest derivation exists and is discarded.
- The instruct tail has the same root: `emitInstruct` (`cmd/mindspec/instruct_tail.go`) calls `phase.ResolveContext(root)` and falls back to `state.Focus{Mode: state.ModeIdle}` whenever the context is nil **or `ctx.Phase` is empty** — which is exactly the no-epic-draft, the multiple-active-specs, and the discovery-error cases (`WorktreeMain` branch, `derive.go:588-597`: >1 specs leaves Phase empty). "Cannot determine" and "truly idle" collapse into the same idle-mode guidance.

**#220/#245 (verbs print idle guidance on success).** `mindspec spec create 128-lifecycle-verb-state-honesty`, run 2026-09-01 from the `main` checkout, succeeded and ended with the idle-mode instruct block — the "Available Actions: `mindspec spec create <slug>` / `mindspec doctor`" text is verbatim `internal/instruct/templates/idle.md:44-48`. The wiring: `spec create`'s success path prints its result lines then calls `emitInstruct(root)` (`cmd/mindspec/spec.go:69-81`), which resolves idle for a draft as above. For `complete`: `completeTail` *does* print a result summary first — `complete.FormatResult` renders "Bead X closed / Worktree removed / Mode: …" (`internal/complete/complete.go:1378-1408`) before the instruct tail (`cmd/mindspec/complete.go:156-166`) — so #245's "no result at all" headline (filed against 0.12.0) is partly addressed at HEAD; what remains is the tail: the same `emitInstruct(root)` fallback renders full idle-mode guidance whenever post-completion context resolution yields no phase (multi-spec, discovery error), and the tail's mode can contradict the `Result.NextMode` the summary just printed. R2 pins result-first ordering *and* tail/result mode agreement; the exact #245 0.12.0 path (result lines entirely absent) must be re-reproduced or declared fixed-by-092 during planning — it was not reproduced today.

**#186 (complete wedges on its own commit) — mechanism confirmed live at HEAD.** The ordering in `internal/complete/complete.go`: the panel gate runs at `:750`, deliberately *before* the artifact-materialization commits — the in-code comment at `:710-715` states "CommitAll advances the bead/<id> tip PAST reviewed_head_sha … so the gate measures the PRE-CommitAll beadHead tip" — then the user `CommitAll` (`:815`) and the pathspec-scoped `.beads` sync commit land, then the doc-sync and ADR-divergence gates validate the committed tip (the ADR-0041 §1 exception). Warn (not block) on reviewed_head_sha mismatch"), so any exemption must be narrower than a downgrade.

## Requirements

Diagnostic and guidance strings changed here are first-class outputs: ACs pin what messages say and what their claimed state is, with red-on-revert tests, never that a string is non-empty. Per the 127 lesson, no AC executes an emitted recovery string; hinted-command outcomes are asserted by invoking the command's own code path on the fixture directly.

### R1 — Honest mode derivation and `state show` (#220)

1. `mindspec state show` never reports `"mode": "idle"` together with a non-empty `activeSpec`. For a draft spec (spec directory + branch exist, no epic), the reported mode is `spec` — or, if OQ-2 resolves to keeping mode strictly beads-derived, an explicitly distinct honest representation (e.g. a `draftSpec` field plus a mode value that is *documented as excluding drafts*); silence-as-idle is not an acceptable resolution.
2. The mode `state show` prints and the mode the context derivation computes may not silently disagree: `state.go`'s composition (`ResolveMode` for mode, `ResolveContextFromDir` for bead) is reconciled so one derivation is authoritative and the other is either removed or asserted-consistent.
3. The **six-verb agreement table** is delivered as a documentation artifact (location decided at plan time; ADR-0023 amendment or a doc it references) pinning, for each verb's success on its canonical state, the post-verb mode that `state show`, the emitted instruct tail, and `DerivePhaseFromChildren` agree on: `spec create → spec`; `spec approve → plan`; `plan approve → plan` (**settled fact 1** — the stored-`implement` reconciliation is OQ-3); `next → implement`; `complete → implement` (mid-spec) / `plan` (remaining beads all blocked — `FormatResult`'s `ModePlan` branch, `complete.go:1396-1400`, a reachable success mode the table may not omit) / `review` (last bead); `impl approve`/`impl adopt → idle`. Each row is cross-checked by a fixture test against the shipped derivation, so the table cannot silently drift from code.

### R2 — Result before guidance; guidance for the actual mode (#220 + #245)

1. Every state-changing verb (`spec create`, `spec approve`, `plan approve`, `next`, `complete`, `impl approve`, `impl adopt`) prints an unambiguous success result *before* any instruct tail, naming what changed (already true for `complete`'s summary and `spec create`'s "Spec initialized" lines — those orderings become pinned by test rather than incidental).
2. The instruct tail renders guidance for the verb's *actual post-state*: `spec create`'s tail renders spec-mode guidance, never `idle.md`; `complete`'s tail mode agrees with the `Result.NextMode` its own summary printed.
3. `emitInstruct`'s fallback distinguishes *indeterminate* from *idle*: when context resolution errors, or yields no phase (multi-active-spec ambiguity), the tail says so ("cannot determine mode: <reason>" + the resolving action) instead of rendering idle-mode "Available Actions" — a failure to derive state is never presented as a derived idle state.
4. During planning, #245's exact 0.12.0 shape (result lines entirely absent) is re-reproduced against HEAD or dispositioned fixed-by-spec-092 with the pinning test from R2.1 as the regression guard.

### R3 — No self-worsening hints; `repair phase` backward-move guard (#248)

1. The plan-approve → first-claim state (epic stored `implement`, all lifecycle children open, none claimed) is captured as a reusable test fixture, with the live 2026-07-25 warning text as its golden expectation baseline.
2. On that fixture, no verb emits a recovery hint whose execution would move the epic backward: the stored-vs-derived mismatch warning either does not fire for a backward disagreement (derived earlier in lifecycle order than stored), or fires without the `repair phase` recovery line, or the recovery line names a safe inspection action — the exact mechanism is a plan-time design decision (OQ-3 interlocks; the emission site is `derive.go:179-193`).
3. `mindspec repair phase` refuses to write a `mindspec_phase` value that moves the epic backward in lifecycle order (`spec < plan < implement < review < done`) unless an explicit force flag with a recorded reason is passed; the refusal carries an ADR-0035 recovery line. (Write site: `cmd/mindspec/repair.go:189-191`.)
4. Scope fence: this requirement covers *this hint class* — the phase-mismatch warning and `repair phase`'s write — not a general audit of all hints (spec 127 owns the destructive-hint class; its finite-floor limitation applies equally here: "is this hint harmful?" is not decidable from the text, so the claim is fixture-based, not universal).
5. The claim-count nuance is inherited honestly: the warning fires up to 3× per `state show` (worktree-dependent, per #248's own conditional analysis) — noise reduction across the duplicate fresh-`phase.Cache` call sites is in scope only if it reduces to sharing one `phase.Cache` across the three named call sites with no new exported API — that is the whole bar; anything larger is out of scope. The harmful-recovery mechanism, not the count, is the requirement.

### R4 — `complete` retry convergence: the #186 real fix

1. After a gate-refused `mindspec complete`, an immediate retry (with the appropriate override for the originally-failing gate, e.g. `--allow-doc-skew`) is decided by the *same* gate class that refused the first run — never by the panel stale-SHA gate blocking against a tip delta authored by `complete` itself.
2. A delta confined to tracker artifacts (`.beads/**`) authored by the tool never invalidates a passed panel — whether by gate ordering, rollback, or an explicitly-computed tracker-only-staleness fact is OQ-1's decision. Whichever mechanism: the fact is computed on the `complete`/caller side and fed into `panel.GateFacts` (ADR-0037's zero-subprocess confinement of `internal/panel` is preserved), and any staleness exemption is pinned to "tool-authored, tracker-paths-only, verified by diff pathspec" — never a general warn-downgrade (ADR-0037 §4's rejected alternative stays rejected).
3. A failed `complete` leaves the bead branch in a state from which the documented recovery is a plain re-run (plus the original gate's override) — no raw-git repointing, no manual `reviewed_head_sha` surgery. The 127-shipped guidance surfaces (e.g. `merge-safety.md`) are updated if the chosen mechanism changes operator-visible behavior.
4. The ADR consequence is priced: OQ-1(a) (reorder) amends ADR-0041 §1 as a reversal; OQ-1(b) (rollback) must define rollback semantics that never touch a preserved merge or user commits (127's never-abort posture); OQ-1(c) (exemption) amends ADR-0037 §4.

### R5 — Proportional claim guard (#179, rebuilt on settled fact 2)

1. Rebuilt requirement: a worktree-creating claim (the only kind — settled) blocks on invoking-worktree dirt **only when the claim operation would actually entangle that dirt**: dirt on paths the claim writes in the invoking checkout (mindspec state/session files; `.beads/**` is already artifact-exempt and auto-handled per ADR-0025). Unrelated user dirt in the invoking worktree does not hard-block claiming into a fresh worktree. This narrows ADR-0025's literal decision sentence "User-authored dirt still blocks" for the claim path, so the default direction carries the conditional clarifying amendment priced in ADR Touchpoints.
2. The protective posture is unchanged: the guard still never advises stash/discard/commit of the human's WIP; when it does block, `DirtyTreeFailure`'s message contract (worktree-context line, final recovery line, steer-to-active-worktree) is preserved.
3. If planning discovers a genuine whole-tree-hygiene rationale the issue analysis missed, the fallback disposition is #179's option 3: keep the block, document its intent, and add a scoped `--allow-dirty` bypass (since `--force` is session-freshness only) — but the default direction is 1, because the guard's own ADR-0025 purpose does not cover untouched dirt.

### R6 — Deterministic, honest bead selection (#187 + #146 remainder)

1. **Pick/emit parity**: `--pick N` is honored on the `--emit-only` path (`runEmitOnly` currently never sees it), selecting the N-th element of the *same* ordered ready set the claim path would use, with the same out-of-range error; a parity test pins both paths to one selection function over one set-construction. The *positional* path's existing asymmetry is pinned, not left silent: on `--emit-only` a positional bead ID resolves via `FetchBeadByID` (`cmd/mindspec/next.go:406-412`), deliberately bypassing ready-set membership — a preview needs no claimable bead — while the claim path keeps `SelectWorkByName`'s ready-set requirement; a test pins both behaviors, and the emit-only output states the mode (e.g. "emit-only: bead fetched by ID; readiness not checked") so the difference is documented in the surface itself.
2. **Ordering**: the ready set mindspec selects from preserves `bd ready`'s returned order (priority-respecting) end-to-end; no post-query step reorders it. The default when multiple beads are ready and no pick/positional is given is decided at plan time (OQ-5: bd-ready order vs plan/bead-number order) and *documented in the selection's own output* ("Defaulting to first item" names the ordering rule). `--pick N` indexes the *displayed* list (`FormatWorkList`'s numbering) — which both paths must build identically per R6.1 — so pick-N always selects displayed row N; equality with `bd ready`'s own row N holds exactly when the step-2.5 filter drops nothing, and R6.3 makes any drop loud rather than silent.
3. **Filter honesty**: the step-2.5 title-substring filter (`containsSpecID`) may not silently change selection semantics: a positional bead ID that is in the epic's `bd ready --parent` set but excluded by mindspec's filtering gets an error naming the actual exclusion reason (e.g. "ready in bd but excluded: title does not reference spec <id>"), never the false "not found or not ready". (Whether the title filter should exist at all when the query is already epic-scoped is a plan-time question; its *outcome* bug-class — "no ready work" spec-done false-conclusions — is #255, out of scope.)
4. **bd stderr passthrough**: when a bd shell-out behind `next` fails, the error surfaces bd's stderr content (available today in `exec.ExitError.Stderr`, discarded by the `%w`-of-exit-status wrapping) so the stale-binary/schema-drift class (#146 #3) is diagnosable from mindspec's own output.
5. **Depends-on disposition — explicit strike, with rationale**: #146 #2(a)'s "parse plan prose `Depends on` blocks into bd edges" is STRUCK, not implemented. Rationale, re-derived: the mechanism shipped structurally instead — `work_chunks` frontmatter → `bd dep add` edges (spec 097 R3, `plan.go:675-693`), with an explicit warning when the block is missing/unparseable (`plan.go:370-372`) and surfaced dep-add failures (spec 119 AC-20). A prose parser would be a second, weaker authority for the same fact (the exact dual-derivation dishonesty this spec exists to remove). The residual gap #146 #2(b) (default-order footgun) is covered by R6.2.
6. **Doctor disposition — explicit strike as shipped**: #146 #3's doctor suggestions are already delivered in full — bd version-floor check (`internal/doctor/beads.go:282-317`), schema-drift detection (spec 103 R2), and the multiple-binaries-on-PATH check (`checkMultipleBdOnPath`, `internal/doctor/beads.go:394-400`: warns on more than one distinct `bd` reachable on PATH, symlink-collapsed; an earlier draft claimed this check "remains unshipped" — stale, corrected by the grill). `mindspec release` (#146's missing release/abandon verb) shipped (`cmd/mindspec/release.go:64`).
