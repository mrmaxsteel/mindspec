# Spec 128-lifecycle-verb-state-honesty: Lifecycle verb state honesty + claim/selection (spec-127 split, part 2)

*Citation scope: all `file:line` citations in this document were resolved against the spec-128 worktree at `06273a19` (branch `spec/128-lifecycle-verb-state-honesty`, forked from `main` after spec 127's merge, PR #236 / `ae45fd7a`) on 2026-09-01, unless a citation is explicitly marked historical (e.g. an issue body's line numbers at an older base). Where an inherited citation had drifted, the refreshed line is given and the drift noted.*

## Goal

After this spec, the lifecycle verbs tell the truth about state and act deterministically on it:

- (a) `mindspec state show` and every verb's instruct tail report the phase the system is actually in — a draft spec is never reported as `idle` alongside a non-empty `activeSpec`, a lifecycle-discovery failure is never serialized as a successful empty or idle mode, and success output is never indistinguishable from a no-op (#220, #245);
- (b) no verb emits a recovery hint whose execution makes state worse on a reproducible state — pinned by the deterministic plan-approve → first-claim `repair phase` regression fixture (#248), and `repair phase` itself refuses a backward lifecycle move it was not explicitly forced into;
- (c) a gate-refused `mindspec complete` converges: an immediate retry meets the *same* gate the first run failed, never a stale-SHA block manufactured by the tool's own tracker auto-commit (#186 — the real fix; spec 127 shipped only the interim mitigation of removing the destructive documented workaround);
- (d) `mindspec next`'s dirty-tree claim guard blocks only on dirt the claim operation could actually entangle, rebuilt on the settled fact that there is no in-place claim mode (#179);
- (e) bead selection is deterministic and honest: a positional bead ID resolves to exactly that bead or errors with the true reason, `--pick N` is honored with `bd ready`-consistent ordering on both the claim and `--emit-only` paths, and a failing `bd` shell-out surfaces bd's own stderr (#187, #146 remainder);
- (f) mode guidance states that implementing an externally-merged or frozen contract still requires a new spec, naming spec 127's shipped adopt path by its real invocation: `mindspec impl adopt <spec-id> --reason "<why>"` (#221).

- `resolve.ResolveModeWithCache` returns `state.ModeIdle` whenever no epic exists for the spec (`internal/resolve/resolve.go:57-67` — "Returns ModeIdle if no epic exists"). A draft spec by definition has no epic (the epic is created at `spec approve`), so every draft resolves as `idle`.

The honest derivation exists and is discarded.
- The instruct tail has the same root: `emitInstruct` (`cmd/mindspec/instruct_tail.go`) calls `phase.ResolveContext(root)` and falls back to `state.Focus{Mode: state.ModeIdle}` whenever the context is nil **or `ctx.Phase` is empty** — which is exactly the no-epic-draft, the multiple-active-specs, and the discovery-error cases (`WorktreeMain` branch, `derive.go:588-597`: >1 specs leaves Phase empty). ## Requirements

### R1 — Honest mode derivation and `state show` (#220)

1. `mindspec state show` never reports `"mode": "idle"` together with a non-empty `activeSpec`. For a draft spec (spec directory + branch exist, no epic), the reported mode is `spec` — or, if OQ-2 resolves to keeping mode strictly beads-derived, an explicitly distinct honest representation (e.g. a `draftSpec` field plus a mode value that is *documented as excluding drafts*); silence-as-idle is not an acceptable resolution.
2. The mode `state show` prints and the mode the context derivation computes may not silently disagree: `state.go`'s composition (`ResolveMode` for mode, `ResolveContextFromDir` for bead) is reconciled so one derivation is authoritative and the other is either removed or asserted-consistent.
3. The **per-verb agreement table** is delivered as a documentation artifact (location decided at plan time; ADR-0023 amendment or a doc it references) pinning, for each verb's success on its canonical state, the post-verb mode reported by the three surfaces the row's fixture asserts — `state show`'s output, the emitted instruct tail's selected template, and the derivation, whose surface for ALL rows is the **status-aware** derivation (`DerivePhaseWithStatus`-class, `derive.go:166`/`:174` — round-4 G1.2: bare `DerivePhaseFromChildren` cannot express the terminal rows, returning `review` for an all-closed child set) — with per-row carve-outs stated in the table itself where the surfaces are *designed* to differ. Rows: `spec create → spec`; `spec approve → plan`; `plan approve → plan` (**settled fact 1**; this row's fixture shape depends on OQ-3 — see the carve-out below); `next → implement`; `complete → implement` (mid-spec — including "remaining beads blocked": blocked is neither closed nor in_progress, so the just-closed bead makes the some-closed branch derive `implement`, `derive.go:383`; the round-2 "all blocked → plan" conditioning was WRONG, re-derived at round-4 G1.1) / `plan` (reachable only via the empty-lifecycle-subset fallback, `derive.go:366` — e.g. completing a non-lifecycle follow-up child of an epic with no lifecycle tasks; ### R3 — No self-worsening hints; `repair phase` backward-move guard (#248)

1. The plan-approve → first-claim state (epic stored `implement`, all lifecycle children open, none claimed) is captured as a reusable test fixture, with the live 2026-07-25 warning text as its golden expectation baseline. **The same warning window has a SECOND deterministic reproduction route (round-2 G2): `release`.** Releasing the sole claimed bead returns the epic to all-open with stored `implement` preserved — and release's own step-6.5 `phase.DerivePhase` call emits the very stored-vs-derived warning + `repair phase` hint on the disagreement it just preserved (`cmd/mindspec/release.go:315-318`). The fixture coverage of this requirement includes both routes — plan-approve-shaped and release-shaped — and R3.2's no-self-worsening-hint assertion runs on both.
2. On those fixtures (both R3.1 routes — plan-approve-shaped and release-shaped), no verb emits a recovery hint whose execution would move the epic backward: the stored-vs-derived mismatch warning either does not fire for a backward disagreement (derived earlier in lifecycle order than stored), or fires without the `repair phase` recovery line, or the recovery line names a safe inspection action — the exact mechanism is a plan-time design decision (OQ-3 interlocks; the emission site is `derive.go:179-193`).
3. `mindspec repair phase` refuses to write a `mindspec_phase` value that moves the epic backward in lifecycle order (`spec < plan < implement < review < done`) unless an explicit force flag with a recorded reason is passed; the refusal carries an ADR-0035 recovery line, and a forced backward write's result line names the recorded reason. (Write site: `cmd/mindspec/repair.go:189-191`; test seam `repairMergeMetadataFn`, `repair.go:28`.) **Concurrency semantics (round-1 G9, REPLACED at round-2 G6 — the round-1 re-derive-before-write only narrowed the window; this closes it).** The invariant: a concurrent lifecycle verb advancing stored phase (e.g. `complete` writing `review`) after `repair phase`'s final derivation but before its metadata write must never be overwritten by repair's stale earlier value. Mechanism, priced concretely: bd's `MergeMetadata` exposes no compare-and-swap, so conditionality is built *above* it with the house serialization primitive — a repo-scoped advisory file lock following `internal/journal`'s existing idiom (`acquireFileLock`: `flock(2)` on unix, O_EXCL lockfile on windows; the `withReportsLock` read-modify-write pattern, `internal/journal/lock.go:55-61`) — held across the read-stored → derive → guard-compare → `MergeMetadata` critical section by `repair phase` **and by every other `mindspec_phase` writer**. The round-2 enumeration of that writer set was INCOMPLETE (round-3 G1, three slots convergent); the full set, re-derived at `9ac301ee` by grepping every `MergeMetadata`/`mindspec_phase` site: `plan approve` (`plan.go:455`), `spec approve`'s existing-epic backfill (`spec.go:76`), `complete`'s step-6.5 sync (`complete.go:1366`), `release`'s sync write (`release.go:152`, fed by the `:315-318` derivation), `impl approve`'s TWO writes — the deferred stale-phase reconcile (`impl.go:577-579`) and the `done` write (`impl.go:611-613`), `impl adopt`'s `done` write (`adopt.go:424` via `:437`), the `repair phase` write itself (`repair.go:189-191`), and `phase.EnsureMigrated`'s ADR-0034 backfill (`migrate.go:59-61`) — which runs AHEAD of every preflight (invoked at `impl.go:277`, `plan.go:300`, `complete.go:522`) and writes exactly when stored phase is absent, so its absent-check→derive→write section must sit inside the lock like any other writer. One rationale-carrying exclusion: `spec approve`'s epic-*creation* seed (`spec.go:84`, `bd create --metadata`) writes the phase into an epic that does not exist until that instant — there is no stored value to race — and is excluded from the lock obligation on that stated ground. **Completeness of this prose list is NOT the load-bearing claim** — the round-2 draft proved a prose enumeration goes stale; the obligation is mechanized the way this spec pins every other drift-prone list (R5.1's enumeration test, AC-14's total classification): a grep/seam-anchored test asserts every `MergeMetadata` call site writing `mindspec_phase` executes inside the lock's critical section (exact test shape is a plan decision; the anti-drift obligation is spec-side, AC-5(vi)). Under the lock, each write is conditional on the stored value read in the same critical section, so repair's guard always compares against a stored value no concurrent writer can move before repair's own write lands. Stated boundary: the lock serializes same-machine processes — the deployment model, since bd's Dolt daemon is local; a hypothetical cross-machine concurrent writer is out of scope and said so. The benign residual that survives is only ordering (two serialized writers land in some order, each self-consistent at its write time), never a stale-over-fresh overwrite. AC-5(v) makes this falsifiable with a concurrent-writer leg.
4. Scope fence: this requirement covers *this hint class* — the phase-mismatch warning and `repair phase`'s write — not a general audit of all hints (spec 127 owns the destructive-hint class; its finite-floor limitation applies equally here: "is this hint harmful?" is not decidable from the text, so the claim is fixture-based, not universal).
5. The claim-count nuance is inherited honestly: the warning fires up to 3× per `state show` (worktree-dependent, per #248's own conditional analysis) — noise reduction across the duplicate fresh-`phase.Cache` call sites is in scope only if it reduces to sharing one `phase.Cache` across the three named call sites with no new exported API — that is the whole bar; anything larger is out of scope. The harmful-recovery mechanism, not the count, is the requirement.
6. **`spec approve` existing-epic replay must not regress phase (round-4 G2 — a #248-class defect exposed by R3.3's writer inventory):** the existing-epic path writes `mindspec_phase: "plan"` unconditionally (`spec.go:76`), so re-running `spec approve` against an epic already at `implement`, `review`, or `done` regresses it to `plan`. Safe-replay semantics are required, chosen at plan time from these admissible dispositions: a true *absent-only backfill* (write only when stored phase is empty), performed inside the R3.3 shared lock; *fail-closed refusal* on an out-of-phase replay, with an ADR-0035 recovery line; or another explicitly justified non-regressing disposition. Under every disposition the output honestly distinguishes a mutation from a no-op (e.g. "phase backfilled: plan" vs "epic exists; stored phase implement untouched" vs the refusal) — a replay that changed nothing never claims to have set the phase.

"Tool-authored" is deliberately NOT part of the pin: a diff pathspec cannot see authorship, so the spec claims the exemption's true paths-only shape and states the accepted residual out loud — *any* actor's commit whose delta is confined to the named artifact file(s) is exempt from staleness — bounded by ADR-0025's own model (the file is a deterministic `bd export` projection; user-authored edits to it are unsupported per ADR-0023, ADR-0025 scope note). **The any-actor residual is an adjudicated accepted cost, not a forced consequence (round-2 G7), with rationale:** (1) the exemption cannot admit code — any non-artifact path in the delta trips staleness (AC-7(ii)); (2) the artifact is not reviewable source and no panel verdict covers its content, so exempting its drift subtracts nothing the review actually asserted; (3) the rejected alternative — treating tracker drift as review-invalidating — is the #186 wedge class itself. Review integrity over source is unchanged. Never a general warn-downgrade (ADR-0037 §4's rejected alternative stays rejected).
3. A failed `complete` leaves the bead branch in a state from which the documented recovery is a plain re-run (plus the original gate's override) — no raw-git repointing, no manual `reviewed_head_sha` surgery. The 127-shipped guidance surfaces (e.g. `merge-safety.md`) are updated if the chosen mechanism changes operator-visible behavior.

The ADR consequence is priced — **every** OQ-1 arm carries an amendment except (c)'s ADR-0041 side: OQ-1(a) (reorder) amends ADR-0041 §1's gate-ordering design as a reversal; OQ-1(b) (rollback) amends ADR-0041's recovery contract as a reversal too — §1's Reconcile phase says "Never a rollback" and §2 is titled forward-reconcile — and must additionally define rollback semantics that never touch a preserved merge or user commits (127's never-abort posture); OQ-1(c) (exemption) leaves ADR-0041 intact and amends ADR-0037 §4.

### R6 — Deterministic, honest bead selection (#187 + #146 remainder)

1. **Pick/emit parity**: `--pick N` is honored on the `--emit-only` path (`runEmitOnly` currently never sees it), selecting the N-th element of the *same* ordered ready set the claim path would use, with the same out-of-range error; a parity test pins both paths to one selection function over one set-construction. The *positional* path's existing asymmetry is pinned, not left silent: on `--emit-only` a positional bead ID resolves via `FetchBeadByID` (`cmd/mindspec/next.go:406-412`), deliberately bypassing ready-set membership — a preview needs no claimable bead — while the claim path keeps `SelectWorkByName`'s ready-set requirement; a test pins both behaviors, and the emit-only output states the mode (e.g. "emit-only: bead fetched by ID; readiness not checked") so the difference is documented in the surface itself.
