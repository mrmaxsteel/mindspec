# Spec 127-lifecycle-verb-trustworthiness: Destructive Recovery and the Externally-Merged Spec (the #218 cluster)

*Citation scope (added at final review, F3-2): all `file:line` citations in this document are pinned to the spec base `09f62bd9` unless explicitly marked as refreshed against the shipped tree (e.g. the R5(d)(v) enumeration's bead-7 refresh note). Resolving an unmarked citation against a later tree may land on moved code; the counts and membership claims, not the line numbers, are what the requirements pin.*

## Goal

No lifecycle verb prints a recovery instruction that would destroy work — a guarantee enforced mechanically over R5's reviewed destructive-command floor, and by review beyond it (the finite-floor limitation, stated in R5(a) and Non-Goals: "is this text dangerous?" is not decidable from the text, so no unqualified "ever" is claimable) — no lifecycle merge executes without work-destruction evidence being consulted, and a spec whose content reached `main` outside the lifecycle has a first-class, audited, merge-free path to its terminal state.

**Provenance of this revision.** The nine-slot spec gate returned 9/9 REQUEST_CHANGES on the draft. Six of nine slots judged the draft's five-bead, seven-issue scope over-compressed (O3 measured ~10 independently-reviewable deliverables), and the gate split the spec. **Spec 127 keeps the GH #218 cluster end-to-end plus the destructive-recovery class it belongs to; everything else — state honesty (#220), `complete` gate ordering (#186), claim/selection (#179, #187, #146), and mode guidance (#221) — moves to follow-on spec 128** (AMENDED at final review, S3-5: not yet filed as a spec — the filing is tracked by bd `mindspec-aytt` (P1, open, "File spec 128"); this spec claims closure of none of them, and their draft-127 requirement text does not survive into this revision). The split boundary is the #218 cluster, not the failure-mode boundary: the recovery hints this spec ships must name the adopt path this spec also ships, and a mode-boundary split would put that dependency across two specs.

**Revision 3, after the six-slot re-gate (6/6 REQUEST_CHANGES on revision 2).** Two mechanisms of revision 2 are *replaced*, not repaired, per the re-gate's convergent findings: (1) AC-3's execute-the-emitted-recovery-line assertion was self-contradictory on its own guard leg, had no R6-satisfying venue, and — decisively — made the test harness the executor of whatever a regressed derivation emits (O2-r2-1/-2, O3-r2-8, S3-r2-2/-3); it is replaced by the **outcome oracle** (AC-3), which never executes an emitted string. (2) The `:1688`/`:1721` conflict-recovery allowlist rationale is **overturned** (C2-r2-1, adjudicated over F3's reachability argument): the preflight gated the product's merge attempt A; the printed command starts a *new* merge B, run by hand through raw git, which the preflight never evaluates — reachability-of-the-emitter and safety-of-the-emitted-command are different questions. Those two lines are **converted** through the evidence-carrying constructor, not registered (revision 3 pinned the printed merge to the evaluated OID; that pinning form itself fell in round 4 — see Revision 4 below; the conversion-not-registration ruling stands). Both dependency inversions are now fixed by construction: the shared predicate lands first (bead 1) and the adopt surface before every hint that names it (bead 3 < bead 4).

**Why this half ships first, inverting the draft's order:** this class is *active work destruction*. In the #218 incident the tool's own printed hint, followed verbatim, would have merged a stale branch whose diff was −13,168 lines. And the class has a live, previously-unnamed instance shipped today (C2-2): plan re-approval sees a closed child, explicitly admits it may be completed work, and still emits `bd delete <id> --force` as its sole machine-greppable recovery command, gated by no verified fact (`internal/approve/plan.go:820-825`). A refusal that is wrong is costly; a recovery hint that is wrong is executed with the operator's guard down, because the tool told them to.

**Target outcome** (pinned to what the ACs deliver — not "structurally impossible", per F1-10/S3-9): after this spec, on every enumerated surface, (a) a destructive-class command appearing anywhere in a lifecycle diagnostic — recovery line, message body, or labeled choice block — can only be produced through an evidence-carrying constructor whose destructive variants cannot be invoked without an evidence result, and a newly introduced static command matching a **reviewed floor family** is red at development time (the repo-wide convention scan) — the floor is a finite reviewed set, not closure, and a destructive command from a family or program outside it is caught by review under the in-diff extension obligation, not by the guard (R5(a)'s stated limitation); (b) every lifecycle merge producer consults one mandatory work-destruction preflight before mutating, with a block + audited `--allow-net-deletion "<reason>"` override; (c) an externally-merged spec reaches its terminal state through an audited, evidence-gated, merge-free adopt surface that the branch-missing refusal names; (d) `mindspec complete <bead>` remains the converging common-case hint everywhere it is correct — it is made safe upstream by (b), not banned syntactically; (e) where the *correct* recovery is itself destructive (the #218 stale-branch deletion), the hint is emitted **with the evidence that proves it right** — this spec does not merely avoid destructive hints, it proves the ones it must emit.

## Background

All citations verified in this worktree (branch `spec/127-lifecycle-verb-trustworthiness`, forked from `main` at `09f62bd9`, v0.14.0). GH #218 is OPEN.

### The incident (#218), in full — including its composite state

A spec whose implementation reached `main` via an external GitHub PR (spec branch deleted, superseded by a git-native rebuild) could not be driven `review → idle`: (1) `impl approve` failed on a raw `git merge-base … exit status 128` (`internal/approve/impl.go:330-332`) with no hint the branch was simply gone; (2) after the operator manually recreated the branch at `main`, the orphan gate refused with `recovery: mindspec complete <bead>` (`implOrphanRefusal`, `internal/approve/impl.go:842-851` + `internal/lifecycle/orphans.go:70`); (3) that recommended merge's diff was **−13,168 lines** — the hint, followed verbatim, deletes most of the codebase.

**The state the incident occurred in is composite** (O1-r2-3): a `review`-state spec with its branch deleted-then-recreated, *plus a closed bead (`autonomous-agents-078.3`) whose stale bead branch still existed* — the orphan is what produced steps 2 and 3, and the documented resolution was `git branch -D` on it, then re-run `impl approve`. Two design consequences: the incident's step (2) means "spec branch missing" and "spec branch present but stale" are *both* observed shapes (F3-1), and **the correct recovery in the incident state is itself destructive** — delete the stale bead branch, never merge it. So this spec's obligation is stronger than avoiding destructive hints: it must *emit* a destructive command in that state and *prove* it is the right one (AC-2(viii), AC-3(i)).

## Requirements

Diagnostic and guidance strings introduced or changed here are first-class outputs: their ACs pin what the messages *say and do* — the hint's **claimed outcome is independently proven by the outcome oracle** (AC-3's mechanism: ground truth re-derived through pinned non-mutating probes, never by executing an emitted string) — with a red-on-revert property, never that a string is non-empty (the W0 lesson; O2-7's sharpening, as corrected by the re-gate: the assertion that falsifies the #218 class is proving the hinted action's *outcome* against the same evidence the hint was derived from, S3-r2-3).

### The shared work-destruction predicate (bead 1 — the root of the dependency graph)

For a candidate merge of branch `B` into target `T`, the evidence classes are pinned at spec level; there is **no numeric floor or ratio at spec level**:

1. **Ancestry** — `B` is already an ancestor of `T` (or of `main`): there is nothing to merge; the safe disposition is branch deletion / no-op.
2. **Supersession** — `B`'s content already landed in `T` or `main` via another route (`lifecycle.FindLandedMerge`, `gitutil.ContentSubsumedOutcome`, `gitutil.NetEffectLanded`): merging the stale snapshot would regress landed work.
3. **Stale-deletion** — the merge preview deletes content present in `T` that `B`'s own authored work never carried: the deletions are artifacts of `B`'s staleness, not authored changes. **"Authored" is grounded in the branch's novel content, NOT in the mechanical commit span `merge-base(B,T)..B`** (AMENDED at the plan-approve ruling, plan-gate round 2 / P1-5, reviser-probed with real git): the span definition this sentence originally pinned specifies an **empty class** — in a three-way merge, a clean preview-deletion of a `T`-present path exists only where the `B` side deleted it relative to the merge base, so every preview-deletion always falls inside `merge-base(B,T)..B` and the "never carried" set is empty by construction; worse, on the very shape the class exists for — a branch recreated from `T`'s tip carrying an old tree — the computed merge-base IS `T`'s tip, so the reverting commit reads as authoring its own deletions and the span definition certifies the destruction as clean. The trap, recorded so it is not re-armed: **a computed merge-base is itself forged by branch recreation, so range membership cannot ground authorship.** The predicate grounds authorship instead in the branch's novel contribution: whether `B`'s tree, net of `B`'s novel paths, reconstructs a prior state of `T` (a staleness artifact → this class) or does not (an authored deletion → clean) — mechanics plan-pinned, probed against the destructive and boundary shapes before any bead is implemented. **"Content the branch never carried" is part of the predicate** (F1-2, ruled — unchanged by this amendment): an honest cleanup bead authors its deletions as its own work and passes clean — no override toll; so does a large rename/move.

**The predicate returns a closed, named outcome set** (enum/variant type: ancestor, superseded, stale-deletion, clean, evidence-error), and every consumer switches over it exhaustively — a new variant without a fixture in every consumer's table is red at development time (O2-r2-4). **The exhaustiveness mechanism is pinned** (B-r4-3 — Go enforces no enum exhaustiveness and `.golangci.yml` carries no `exhaustive` linter, so "red at development time" needs a mechanism, not an aspiration): an iota enum with a count sentinel; every consumer's fixture table asserts `len(table) == outcomeCount`; consumer switches carry no `default` arm over the type. **Per-consumer outcomes are pinned** (F3-r2-1): at the R4 *merge preflight*, `ancestor` proceeds as a no-op — the documented post-conflict recovery flow depends on the re-run converging via ancestry (`mindspec_executor.go:1649-1653`); `superseded` and `stale-deletion` refuse; at the R2 *hint derivation*, `ancestor` yields the deletion hint. The plan chooses mechanics (which primitive answers which class, read-only throughout) and MAY add a numeric leg only as a *secondary, conservative tripwire* (F3-5); the AC-8 must-pass fixtures (large rename; honest cleanup; post-conflict re-run) make a bare deleted-line floor unimplementable. **Evidence unavailable or uncomputable (git error, missing ref, inconclusive primitives): absence of evidence is never treated as safety.** Preflights refuse fail-closed with a named retryable error, the audited override remaining available (F3-3); hints degrade to inspection-first, never to the destructive action (S3-9). Every predicate consumer below states its evidence-unavailable behaviour explicitly (O2-2's generalization).

### R1 — An audited, merge-free adopt path

For the case where a `review`-state spec's content reached `main` by another route:
(a) An explicit, operator-invoked surface (naming — flag on `impl approve` vs. sibling verb — is plan-level per the 125 precedent; every AC that names the invocation resolves it *in full, including flags*, per AC-11) transitions the spec to its terminal state: closes the epic, writes the finalize export, records an audit marker (reason, acting identity, timestamp, invoking operation) via the existing helpers (the 124 `--allow-not-ready` / 125 reattest pattern — detectable-by-inspection, not claimed tamper-proof). It performs **no spec→main merge**; any main-side delta is confined to the finalize-export artifact.
(b) **Positive landed evidence is required** (C1-5, F1-4), and the aggregation is a **pinned three-valued lattice with an epic-coverage clause** (C-r4-1/-2/-3, B-r4-5, D-r4-4). **Sources** (O3-r2-2 — the 125 primitives are all ref-keyed, so "consumption not research" holds only where a ref survives): (i) the remote spec-branch ref, **corroborated via the fetch route, pinned as the single sanctioned mechanism** (F-r5-1 — revision 4's "equality OR fetch" disjunction contradicted AC-2(ix)'s stale-tracking-ref row, which only the equality route could satisfy, while the cited wu7t precedent at `mindspec_executor.go:812-825` *is* fetch-then-evaluate; a requirement may not bless a mechanism its own AC forbids): a fresh `gitutil.FetchRemoteBranch` precedes evaluation, and every landed/net-effect probe runs **at the freshly fetched remote tip, never at the pre-fetch tracking ref** — the bare local `origin/<specBranch>` tracking ref is a cache and is never evidence by itself, and `RemoteHeadSHA` equality with it is not an accepted substitute for the fetch; an absent remote branch or an unreachable remote is **error**, never positive — this presupposes a **configured** remote; when no remote at all is configured, source (i) is treated as simply not existing, the same no-route disposition a bead with no surviving branch has, never error (bead-3 fix round, O3-ruled required, not merely permitted: the error-dominant reading would make AC-1's bead-branches-only evidence form mechanically unsatisfiable on a from-scratch local workspace); (ii) the epic's bead branches, the epic enumerated at **`bead.AllStatuses` breadth** (the `phase.fetchChildren`/spec-103-R4 precedent, `cache.go:272-286` — never the closed-only `ClosedEpicBeadIDs` walk, under which a non-closed bead's surviving unlanded branch could not poison the verdict), each surviving branch evaluated per-branch; **a failure to resolve the full status set during enumeration is evidence-error for the aggregate, never a silently narrowed enumeration** (F-r5-2 — the cited precedent's own lines carry the trap: `cache.go:281-291` degrades to built-in statuses when workspace-root resolution fails, which would make a custom-status bead invisible to the coverage quantifier; an implementation copying the precedent verbatim inherits a fail-open narrowing this clause forbids). Each per-source result is **three-valued** — positive / negative / **error** (`NetEffectLanded` returns `(bool, error)` and never guesses an infra failure into a boolean; the lattice must not either). **Lattice, pinned**: any negative → negative for the whole (refusal names inspection + the attestation escape); no negative but any error → **evidence-error** (fail-closed retryable refusal, wording distinct from the negative refusal per R3a(ii)'s precedent; attestation availability per (c)); positive additionally requires **epic coverage**: every bead of the epic is positively evidenced — by its surviving bead branch evaluating landed, or by a landed merge identified for it on the corroborated-and-fetched spec ref (`FindLandedMerge` over that ref) with that tip subsumed in `main`. A bead with no surviving evidence-bearing route makes verified adopt **unavailable** (evidence-absent → attestation), exactly as the zero-source case: one-of-N surviving-and-landed is never a VERIFIED adopt (B-r4-5). Stated honestly: quantification is over the bd-enumerated epic; a surviving `bead/*` ref with no bd row is outside the evidence model (R3c gates the deletion hint that manufactures that state). When no ref-bearing source exists, or sources conflict (e.g. corroborated spec ref positive while a surviving bead branch is negative), **verified adopt is unavailable by design**: the refusal mutates nothing and names inspection plus the attestation escape in (c). **Refusal classes are textually distinct** (F-r5-3): the negative, sources-conflict, evidence-error, and unavailable-uncovered refusals each carry a distinct class marker in their wording — not one shared inspection-plus-attestation shape — and each AC-2(ix) row asserts its own marker; three rows satisfiable by one indistinguishable message would let an any-positive-wins aggregation bug hide behind the coverage clause. A deleted branch is not proof of an external merge, and this spec ships no branch-less landing oracle.
(c) **Attestation escape — trigger set pinned** (C-r4-8): a distinct, explicit flag, honoured in exactly three aggregate states — **no ref-bearing source**, **evidence negative**, and **evidence-error** (on the error refusal, retry is named first and attestation second); it is never honoured over an all-positive-with-coverage aggregate (nothing to attest past). Its audit marker records in its own wording that **landing was NOT verified and was operator-attested**, **and records which trigger state it was exercised in** — no-source | negative | error (F-r5-4: attesting past a definite negative is materially more suspicious than attesting with no source at all, and the audit trail must be able to distinguish them; a pattern of attest-past-negative is the friction signal that would justify tightening) (C1-5's alternative, adopted as the escape rather than the default). **Negative stays in the trigger set deliberately** (the round-5 ruling): removing it would not prevent attest-past-negative — it would incentivise `git branch -D` on the negative evidence first, flipping the aggregate to no-source, which *is* in the set; excluding negative would launder the attestation through exactly the destructive act this spec exists to eliminate, while destroying the evidence an auditor would want. In the #218 incident's own deleted-and-rebuilt shape — where the surviving bead branch is *stale*, i.e. negative evidence — this is the honest terminal route, and the closes-map says so.
(d) **Branch-present refusals are evidence-aware** (F1-3, F3-1): with the spec branch present and *current* (not superseded), the refusal names the normal path; with the branch present but *stale* per the predicate (the #218 step-2 recreated-branch shape), the refusal names inspection + stale-branch deletion + adopt rerun — never a bare "the normal path applies", because in that state the normal path is the destructive merge.
(e) **Direct call sites are enumerated; indirection is review-caught** (AMENDED at bead-3 fix round 2, G1-B3-05/O2-NEW1-ruled, following the bead-2 same-package ruling — R5(b)'s precedent): `cmd/mindspec/impl_adopt_test.go`'s call-site enumeration (`TestAdoptSpec_OnlyDirectProductionCallSiteIsItsCommandHandler`, O2-8's rewrite of the untestable negative universal) pins that the only **direct** call site of `approve.AdoptSpec` — a `CallExpr` whose `Fun` is the imported `SelectorExpr` or a dot-imported `Ident`, resolved by import-path IDENTITY (O2-1) — outside the test package is the registered command handler. **The prior wording overstated what an AST walk can enforce** (G1-B3-05's structural finding: the scan is syntax-shaped, not object/call-graph based, the identical limitation R5(b) already records for same-package construction): a package-level `var f = approve.AdoptSpec` plus a second production function calling `f(...)` adds a genuine second production reference to `AdoptSpec`, yet the enumeration still reports exactly one call site and PASSES (O2-NEW1, verified empirically) — there is no `CallExpr` whose `Fun` is the imported selector at the indirect call point; the same blind spot covers a method value or an interface satisfied by a wrapper. So: this requirement pins that the only **direct** call site of the adopt entrypoint is its registered command handler; reachability through a function value, method value, or wrapper-satisfied interface is **not** mechanically detected and is **review-caught**, under the same in-diff extension obligation as R5(a)/R5(b)'s residual classes — never a claim this test makes. The intent is unchanged: adopt must not be reachable as an incidental side effect from a second production call site.
(f) **No third terminal shape**: adopt's durable post-state (epic closed, `mindspec_phase=done`, finalize export present) is asserted *equal to a normal `impl approve`'s* in a comparison fixture, so the surface cannot invent a divergent done-state (C1-3's ambient-vs-targeted table question travels to spec 128; durable markers are the observable here).
(g) **The composite incident state is a first-class fixture** (O1-r2-3): adopt invoked with a closed bead's stale bead branch still present refuses before mutation, and its refusal renders the R2-derived hint — inspection first, evidence-proven stale-branch deletion, adopt rerun — never `mindspec complete`. Adopt's orphan-present refusal joins R2(a)'s emitter enumeration. (Until bead 4 lands the derivation, bead 3's interim orphan-present refusal is inspection-first with no destructive command — stated in the Decomposition so the interim state is priced, not discovered.)
*Falsified if*: adopt performs any spec→main merge; proceeds without a reason; proceeds with negative/absent evidence and no attestation; a VERIFIED marker is written without epic coverage or without remote corroboration; an error result is folded into negative or treated as positive; its audit record omits or blurs the verified-vs-attested distinction; the branch-present-stale refusal steers to the normal path; the orphan-present state draws a `mindspec complete` hint; a second **direct** call site of the adopt entrypoint (a `CallExpr` resolving by import-path identity to the imported selector, per R1(e)'s amended scope) outside the registered command handler stays green — reachability through a function value, method value, or wrapper-satisfied interface escaping detection is the stated review-caught limitation, not a falsifier.

### R2 — Orphan recovery hints are state-derived, through one constructor

(a) **Single derivation**: all four production consumers of the orphan hint (`complete.go:520`/`:552`, `impl.go:850`, `orphaned_beads.go:100`) render it from **one derivation function that takes a predicate outcome and cannot be called without one** (O2-7's structural leg), returning the closed outcome type plus its rendered lines. A call-site anti-drift test enumerates every emitter that renders an orphan recovery line — including R1(g)'s adopt refusal — so a new surface cannot bypass the evidence check.
(b) **Pinned outcomes, one per predicate class, mapped 1:1 onto AC-3's legs** (O1-r2-1, O2-r2-4): bead branch **ancestor of `main` but not of the spec branch** → the hint names branch deletion, never a merge (this — not ancestor-of-spec — is the reachable case: an ancestor-of-spec branch never becomes an `Orphan` at all, `orphans.go:55-57` and `:181-190`; stated so nobody builds the dead fixture — F3-4/O3-11); **superseded / landed via another route** → the hint names stale-branch deletion plus the R1 adopt path by its full invocation; **stale-deletion shape** → the hint names inspection first (a concrete `git diff` command included) and states plainly that merging would delete landed work; **normal unmerged orphan** → the hint remains exactly `mindspec complete <bead>`, unchanged — the converging common case, safe by construction once R4 preflights the merge it triggers; **evidence unavailable/error** → inspection-first, never the merge (S3-9's leg). **Destructive hints carry their proof** (Target outcome (e)): a deletion hint states the evidence class that licenses it, and when the doomed branch carries commits unreachable from `main`/spec, the hint says so and names preservation first (e.g. tag before delete).
(c) **The doctor FixFunc is gated by the same outcome** (O3-r2-3): `orphaned_beads.go`'s `FixFunc` is populated **only** for the `normal unmerged` outcome (where `mindspec complete` is the correct action, itself R4-preflighted); for ancestor/superseded/stale-deletion/evidence-error outcomes the Check carries no FixFunc, so `doctor --fix` mutates nothing in those states. The verb's output and the verb's action derive from one value and cannot disagree.
(d) **Sweep scoping** (O3-9): `StaleOpenBead` (`stale_open.go:67`) and `FinalizeOrphan` (`finalize_orphans.go:92`) hints are **out** of the derivation change — the former is correct (reconcile convergence, `complete.go:867-875`), the latter already state-derived — and both are registered in R5's convention with those rationales.
*Falsified if*: any consumer emits a merge-shaped hint for an ancestor/superseded/stale-deletion branch; the derivation is callable without a predicate outcome; an orphan-hint emitter exists outside the enumeration; `doctor --fix` mutates anything in a non-normal outcome state; the outcome oracle disproves any leg's claimed outcome (AC-3); the common-case hint changes.

### R3 — Approve-surface refusals are gated by verified facts

(a) **Branch-missing preflight in `impl approve`** (the #218 step-1 wedge): branch existence is resolved as a preflight fact before any merge-base or other git plumbing touches the branch name; a missing spec branch produces a refusal naming the absent branch, the external-merge likelihood, and the R1 adopt path by its full invocation. No raw `exit status 128`, and no wrapped `*exec.ExitError` escapes to the operator (O2-8's positive form). **Branch existence indeterminate (probe error) is its own leg** (O2-r2-8): a fail-closed retryable refusal, distinct in wording from the branch-absent refusal, that does **not** name adopt as the disposition — "could not determine" never becomes "absent".
(b) **Branch-present-but-stale**: `impl approve`'s finalize merge is guarded by R4's preflight (the spec→main producer), so a recreated/stale spec branch refuses before mutation instead of merging the stale snapshot (F3-1's fixture). *Delivered by bead 6 with R4; stated here for requirement completeness and assigned there in the Decomposition (O3-r2-5).*
(c) **Plan re-approve closed-child provenance** (C2-2 — the live instance): the closed case at `plan.go:820-825` emits `bd delete <id> --force` **only when durable state positively establishes partial/interrupted provenance** (the mechanics — e.g. absence of a bead branch, absence of landed-merge evidence, supersede-run markers — are plan-level; the direction is pinned: deletion requires positive provenance). When evidence indicates completed work, **or is ambiguous or unavailable**, the refusal preserves the record and names inspection/reconciliation instead. **The provenance evidence is resolved in the `ApprovePlan` preflight — where the children are already resolved — and passed into `checkExistingBeadsSafety` as a value**, preserving that function's documented no-I/O purity; the check itself acquires nothing, so AC-6 stays a pure, hermetic table test (S3-r2-5). The model is the sibling site `plan.go:715-728`, whose deletion hint carries by-construction provenance. `bd delete … --force` joins R5's destructive classifier, and **both plan.go sites route through the constructor** — neither may take the allowlist route (O1-r2-6/C2-r2-2: the final allowlist is exactly pinned, and these are not in it).
*Falsified if*: a missing branch still surfaces a merge-base error; an indeterminate existence probe is treated as absence or routes to adopt; a stale recreated spec branch reaches the finalize merge unguarded; a closed child with completed-work or ambiguous evidence still draws a `bd delete --force` hint; an evidence-free deletion hint passes the convention scan.

### R4 — One work-destruction preflight, every merge producer

(a) A single mandatory preflight API evaluates the shared predicate **before any lifecycle merge mutation**, consulted by all three producers: `CompleteBead`'s bead→spec merge (`mindspec_executor.go:411`), `FinalizeEpic`'s bead→spec auto-merge (`:703`), and the direct spec→main merge (`:916`). **Siting is pinned** (O1-r2-2): the work-destruction facts are resolved in each verb's ADR-0041 §1 preflight phase — for `complete`, before the step-2.5/3 artifact-materialization subphase — and this is sufficient because the destruction classes are properties of the branch's *committed history*, not of the pending commit: commits authored in the current run fall inside the authored range by construction, so they cannot create a stale-deletion the preflight missed, and new commits cannot make a branch *more* superseded. The producer-site consultation is a backstop assertion that the preflight-phase evaluation ran in this run for this bead→target pair — stated plainly (A-r4-1's residual, dispositioned): the evaluated tip and the merged tip may differ by exactly the run's own materialization commits, and the argument above covers the *outcome classes*, not tip identity; nothing downstream relies on tip identity now that R5(d) re-enters the product instead of replaying a pinned commit. The user-facing refusal fires only in the preflight phase, so **no R4 refusal leaves a tool-generated commit on the bead branch** (the #186 stale-SHA wedge is not re-armed by this spec). On the direct spec→main leg, the preflight is **hoisted above the cleanup block** (F3-r2-3; the `guardMergeLayout` precedent at `mindspec_executor.go:845-857`) — a refusal fires before any worktree or branch removal. A chokepoint anti-drift test enumerates every `gitutil.MergeInto`/`MergeBranch` call site its AST vocabulary can resolve in the lifecycle/executor packages and asserts each **consults** the preflight (consultation, not call-site adjacency — F3-r2-3), so a new raw producer reached through a resolvable indirection cannot bypass it (C2-1's required form) — AC-7(iv) states the scan's exact resolved vocabulary, its fail-closed legs, and its review-caught residual. **Seam discipline** (S3-r2-6): the preflight consumes `gitutil.NetEffectLanded`/`lifecycle.FindLandedMerge` through the same symbols the existing `netEffectLandedFn` seam pins (`mindspec_executor.go:1419-1426`), and its seam default joins the spec-121 AC-17 anti-drift consumer set — no private reimplementation, no second independently-rewirable seam. The existing `:819` protected-main probe stays fail-open *by spec 121's design* while R4's preflight is fail-closed; the two postures on one predicate are a recorded decision, not an inconsistency.
(b) A refusal happens **before mutation** (observables pinned in the AC preamble), names the evidence, and offers the audited override `--allow-net-deletion "<reason>"`, recorded like `--allow-doc-skew` on epic metadata **and registered in the escape-hatch friction registry** — `cmd/mindspec/selfemit.go`'s `escapeHatchFlags` and `internal/redact`'s `EscapeHatchTokens` — so repeated overrides are visible to friction reporting (O3-10). **Its position in `detectFriction`'s deterministic first-flag-wins order is stated in code** (S3-r2-7: one admission per entry; when several hatches are bound in one run only the first in order is recorded — AC-7(ii)'s fixture therefore binds only this flag). Block + audited override is the gate's unanimous OQ-1 ruling: an autonomous agent pastes what the tool prints and scrolls past warnings, so warn-only makes the tool's output the destructive keystroke.
(c) **Per-class outcomes at this consumer** (F3-r2-1): `ancestor` → proceed as a no-op (the post-conflict re-run's convergence depends on it); `superseded`/`stale-deletion` → refuse; `evidence-error` → **fail-closed and retryable**, override available (F3-3; the `:640-659` precedent). **A merge failure that produced no merge state is not a predicate outcome and not a conflict** (E-r5-4): `git merge` refusing to *start* over a dirty index/worktree leaves no MERGE_HEAD and no conflicted files — that class is a **worktree-state refusal**, defined at R5(d)(vi), and never enters this table.
(d) **The common path is untouched**: an ordinary bead merge's behaviour is byte-identical to the pre-change baseline (AC-8's leg i, against the committed golden), and the post-conflict manual-resolution re-run converges with no refusal and no override (AC-8's leg v).
*Falsified if*: any producer merges the #218 shape without refusal/override; an override lands without both the metadata record and the journal friction admission; an evidence error falls through to the merge; the ordinary-merge baseline changes; the post-conflict re-run demands an override; a refusal leaves a tool-generated commit on the bead branch; a `MergeInto`/`MergeBranch` call site exists outside the preflight enumeration.

### R5 — The destructive-guidance convention, enforced

The ADR-0035 amendment's red mechanism (F3-2, C2-1, C2-3):
(a) **Classifier**: `internal/guard`'s destructive-command classification expands from the single Req-19 entry to a **closed set of named token-aware families** (D-r4-1 — the floor must be closed over the live discard forms, not a sample of them): `git merge`; `git reset`; `git restore`; `git clean -f`; `git branch -D`; `git push --force` / `git push -f`; `git stash drop` / `git stash clear` (live today in the agent block AC-10 removes); `git worktree remove … --force` **and its short form `-f`** (likewise live); the pathspec-discard forms `git checkout -- <path>` / `git checkout <ref> -- <path>` and `git switch --discard-changes`; **the forced-checkout forms `git checkout -f` / `--force`** (lab-verified to discard uncommitted tracked edits — G-r5-2); **ref-destruction forms `git update-ref -d`, `git tag -d`, `git push --delete` and the refspec-deletion spelling `git push <remote> :<ref>`**; **the irreversible chain `git reflog expire` / `git gc --prune`**; `rm -rf`; and `bd delete … --force` (the plan may extend the family set; it may not shrink this floor). **Option-cluster equivalence is pinned**: single-dash clusters and flag orderings match their family (`git clean -df`/`-fdx`, `rm -fr`/`-Rf`) — a re-spelling is not an escape. **Global-option normalization is pinned** (H-r6-8 — `git -C <path> <subcommand>`, this repo's own house style for operating on another worktree, interposes a global option and its operand between `git` and the subcommand, evading token-aware family matching with no adversarial intent; lab-verified destructive, live seven times in the swept globs): before family matching, the classifier strips git's global options and their operands from a closed pinned set — `-C <path>`, `-c <key=val>`, `--git-dir=…`, `--work-tree=…`, `--exec-path=…`, `-p`/`--paginate`, `--no-pager` — and matches families on the normalized token stream, so `git -C <path> reset --hard` matches the reset family (AC-9(i) probes it). (d) **Conflict-recovery re-entry — replaces revision 3's OID pinning, which round 4 broke empirically** (A-r4-1/-2/-3, nine real-git labs; the pre-registered fallback, now the design): a printed raw merge line cannot be made preflight-equivalent — a merge has two operands and a printed line pins at most one (`git merge <OID>` merges into whatever HEAD the pasted-into worktree is on; the printed `cd` is scrollback, not a pin); by R4(a)'s own siting, the preflight-evaluated tip is not the tip that conflicted whenever the run authored materialization commits (the common case — `complete.go:644-648`); and post-refusal source drift is silently excluded from an OID paste while its subject still claims the branch, tripping spec-125's differing-second-parent fail-closed identity (`landed.go:505-515`) and losing the loud ref-existence failsafe of a branch-name form. So **neither conflict emitter prints a raw `git merge` line at all**. Recovery re-enters the product: the printed recovery names a **conflict-resolution re-entry invocation of the owning lifecycle verb** (`complete` for `:1688`, `impl approve` for `:1721`; the flag's naming is plan-level, and every AC naming it resolves per AC-11). The re-entry surface (i) **re-runs the R4 preflight at invocation time over the current operand tips** — post-refusal drift is included and gated, never silently dropped; (ii) **resolves its own target worktree and branch**, so neither operand is scrollback-pinned (A-r4-3's two-operand point); (iii) starts the merge and on conflict stops **in place** — conflict state left for the operator, no refs mutated — and is a **resumption surface, not start-only** (E-r5-1: stop-in-place makes the surface's most likely *next* invocation happen with a merge already in progress, and lab evidence showed the plain re-run's unconditional abort destroys a staged hand-resolution while `MergeBranch`'s checkout-first shape, `gitops.go:133-137`, silently un-merges a resolved index): on every invocation it resolves its target, then consults in-progress-merge state **before any merge or checkout** — with unmerged index entries present, it re-prints the resolution steps for the existing merge and exits (no new merge, no checkout, no abort); with the index resolved and MERGE_HEAD present, it **completes the product-initiated merge with the seeded subject** (never a checkout, never an abort). **`abortMergeState` is deleted outright, not given a precondition — no path, from any invocation, aborts a fresh conflict** (AMENDED at bead-6 fix round 1, G1-1-ruled, orchestrator-ADOPTED): the wording this sentence previously pinned — a precondition gating which merges `abortMergeState` may abort, preserving today's abort-and-refuse behaviour on the default no-flag path — described a dual design the shipped implementation does not build. `abortMergeState` no longer exists in the tree, and `resumeAwareMerge` (`internal/executor/merge_resumption.go`) never calls `gitutil.AbortMerge` on any path, product-initiated or not. **Why**: threading a second flag through the already-changed interface, or the abort/resumption interaction the dual design would require, is materially more complex than never aborting — and abort-then-replay-from-scratch is exactly the destructive pattern this same clause's own lab evidence already convicts, two sentences above: *"lab evidence showed the plain re-run's unconditional abort destroys a staged hand-resolution"* is a reason to never abort, not a reason to gate when to. **Panel disposition, since this landed unreviewed and was reviewed after the fact**: S1 and S3 ruled the never-abort simplification SOUND; under never-abort that guarantee is vacuous, because nothing ever aborts. Its successor is `classifyPreservedMergeBinding` (`internal/executor/merge_resumption.go`), consulted before either resumption leg above acts on a preserved `MERGE_HEAD`: it classifies the preserved merge against the requested source branch's CURRENT tip as **exact** (no drift — unchanged behaviour), **drifted** (the source has advanced past the preserved tip since the conflict began — once the staged resolution is complete, the preserved merge is completed first, at its original seeded subject, then the source's current tip is incorporated via a fresh merge before success is reported, so nothing authored after the conflict began is silently dropped), or **foreign** (the preserved merge is neither the requested source's tip nor an ancestor of it — another bead's, or an operator's own, preserved conflict occupying the same worktree) — a foreign merge is refused, naming the mismatch, never completed and never treated as this run's own; **The outcome oracle** (AC-3's mechanism, referenced by other ACs): for each emitted hint, the test asserts three properties without ever executing an emitted string. **Well-formed — byte-match for BOTH line classes** (B-r4-2, D-r4-5: resolution alone is existence-shaped — it proves a line *names* a real command, not that it *is only* that invocation, so a compound tail would pass unjudged): every emitted line byte-matches a pinned per-outcome template, parameterized only by validated identifiers/OIDs; `mindspec`-shaped templates *additionally* resolve per AC-11 (resolution proves the template names a live command; the byte-match proves the line is only that invocation); the grammar consumes the **entire line**, and any unconsumed residue or shell metacharacter (`&&`, `;`, `|`, backticks, `$()`) is a test failure. Two injection fixtures pin the fail-closed claim: a compound line (`mindspec complete <id> && git push --force`) and a resolvable-but-wrong mutating leaf (`mindspec doctor --fix`) both fail WELL-FORMED. **Right — with an independence clause** (B-r4-1): the fixture's ground truth is re-derived through raw test-side probes — `git merge-base --is-ancestor`, `git rev-list`, `git for-each-ref`, `git diff --name-status`, and a test-side invocation of raw `git merge-tree --write-tree` — and the ground-truth computation **must not import or call the shared predicate, the hint derivation, or the exported landed/net-effect classifiers** (`FindLandedMerge`, `ContentSubsumedOutcome`, `NetEffectLanded`): the only exported `neteffect.go` surfaces are the classifiers the predicate itself consumes (the raw merge-tree wrapper is unexported), so an oracle that calls them re-derives nothing — agreement would be guaranteed against any bug in the shared code. Divergence between probe-derived truth and predicate outcome is a test failure. The probes prove the hinted action achieves its stated result and destroys no pre-existing work: for a deletion hint, the preview proves the merge alternative would delete landed content, and the probes report whether the doomed branch carries unlanded commits (the hint's preserve-first clause pinned accordingly); for the merge-disposition hint, the preview proves the merge lands the bead's content and deletes nothing `T` carries outside `B`'s authored range. **Harmless-by-construction** — the harness executes only the probe set; a regressed derivation can fail the test but can never make the test run what it emitted.
