# Spec 127-lifecycle-verb-trustworthiness: Lifecycle Verb Trustworthiness

## Goal

Every lifecycle verb is honest about the state it produced, recoverable when it fails, and never hints at an action that destroys work.

Three failure modes, each observed in the field, organize this spec — the spec is structured around the modes, not around issue numbers, because issue-shaped fixes miss the class:

1. **The verb lies about the state it produced** (GH #220). `mindspec spec create` succeeds — branch, worktree, `spec.md` all created — and then, in the same breath, emits idle-mode "No Active Work" guidance; `mindspec state show` reports `{"mode": "idle"}`. Success is indistinguishable from a no-op. The command's own `--help` promises "sets state to spec mode" (`cmd/mindspec/spec.go:31`) and ADR-0023's own derivation table mandates "No epic with matching `spec_num` → **spec** (draft, not yet approved)" (`ADR-0023.md:98`) — the implementation (`internal/resolve/resolve.go:59-61` returns `ModeIdle` whenever no epic exists) violates both.
2. **The verb wedges with no way forward** (GH #186, #218, #221, plus the #179/#187/#146 claim-and-selection residuals). `complete` auto-commits its own tracker sync *before* running fallible gates, so a gate rejection strands the branch past `reviewed_head_sha` and the retry hits a *different*, more confusing gate; `impl approve` hard-fails on a raw `git merge-base … exit status 128` when the spec branch is simply gone; the claim guard blocks on dirt the claim would never touch.
3. **The verb's own recovery hint destroys work** (GH #218). `Orphan.RecoveryCommand()` (`internal/lifecycle/orphans.go:70`) unconditionally returns `mindspec complete <bead>`. In the observed incident the named bead branch was a stale diff-era snapshot whose merge diff was **−13,168 lines**; following the tool's own hint verbatim would have deleted most of the codebase. This is the most dangerous mode and the least represented in the issue text: a refusal that is wrong is annoying, but a *recovery hint* that is wrong is executed with the operator's guard down, because the tool told them to.

Target outcome: after this spec, (mode 1) `state show` and each verb's emitted guidance agree with what the verb just did, pinned by a per-verb agreement regression that catches the whole class; (mode 2) a failed `complete` leaves the branch exactly where the panel reviewed it and a retry hits the *same* gate, a tracker-only delta never invalidates a passed panel, a claim is blocked only by dirt it would actually touch, and an externally-merged spec has a first-class audited path to `idle`; (mode 3) every recovery hint on the touched surfaces is derived from verified current state — supersession-, ancestry-, and net-deletion-aware — and a hint that would destroy work is structurally impossible on those surfaces, pinned by tests of what the hints *say and do*, not that they exist.

## Background

All citations verified in this worktree (fork of `main` at `09f62bd9`, v0.14.0). All seven issues are OPEN: #218, #186, #220, #179, #221, #187, #146.

### First-hand reproduction during this spec's own creation

#220 reproduced while creating spec 127 itself: `mindspec spec create 127-lifecycle-verb-trustworthiness` succeeded — created `spec/127-lifecycle-verb-trustworthiness` and its worktree — and its trailing guidance printed "*# MindSpec — No Active Work / You are not currently working on any spec or bead.*"; `mindspec state show` then reported `{"mode": "idle"}`. The verb lied about the state it had just produced in the same output that produced it. A second, adjacent defect hit during the same creation: a bare-slug first attempt allocated spec **988** instead of 127, because `nextSpecNumber` (`cmd/mindspec/spec.go`) takes `max+1` over spec dirs in every worktree and a transient test-created directory poisoned the scan. That bug is filed separately as `mindspec-m93q` (P1) and is **not** in this spec's scope — it is cited here only as corroboration of the underlying disease: lifecycle verbs derive state from ambient filesystem/tracker conditions without sanity gates, and report state without checking it against what they just did.

### Subsumption truth — why these issues are still open

The superseded roadmap claimed shipped spec 119 subsumed #186/#187/#179/#146. It did not: `119/spec.md:97` declares "*no relaxation of `next`'s existing blocking behavior*" a Non-Goal, and `:78` names #186's mechanism a valid forward-reconcilable outcome, out of scope. That false claim lost this residual for ten specs. This spec therefore ties **every** closure claim to a specific acceptance criterion (see *Issue disposition* under Scope); anything only partially addressed is named and left open there.

### Corrected fact models (both roadmap-panel BLOCKING corrections, orchestrator-reproduced)

- **#186**: `panel.GateFacts` (`internal/panel/gate.go:94-127`) has **10 fields** (`BeadID`, `SkipEnv`, `Reg`, `Res`, `HeadSHA`, `MissingRef`, `GitErr`, `WorktreeAbsent`, `WorktreePath`, `UserDirt`) — not one. The residual is *adding a content-confinement fact* distinguishing "the only delta since `reviewed_head_sha` is the tracker-artifact commit" from "real source changed" — not widening a one-field struct. The wedge itself is two coupled orderings in `complete`: the artifact-sync auto-commit (`internal/complete/complete.go` step 3, `exec.CommitPaths(checkPath, "chore: sync beads artifact", …)`) lands *before* the fallible gates, with no rollback; and the panel stale-SHA gate (`internal/panel/gate.go:241-249`, "commits landed after review; bump round and re-panel") treats that tool-generated, tracker-only commit as a review-invalidating change.
- **#179**: the guard does **not** halt every multi-bead run. `cmd/mindspec/next.go:112-130` is already artifact-aware (dirt confined to `.beads/issues.jsonl` is auto-handled per ADR-0025) and blocks only on **user-authored** dirt in the **invoking** cwd. The real, narrower defect: ordinary operator WIP in the invoking checkout blocks a worktree-creating claim whose `git worktree add` would never touch that WIP. `internal/next/guard.go`'s `DirtyTreeFailure` already steers to the active worktree when one exists; the gap is the new-claim case, where no active bead worktree exists yet and the guard evaluates the wrong tree. The **session-freshness gate** sits immediately above the dirty guard in the same function (`cmd/mindspec/next.go:93-110`, Step 0c) and is the same claim-time trust surface: `--force` bypasses freshness but *not* dirt, and neither refusal states that coverage — an operator discovers it only by trial.
- **#187**: `runEmitOnly(specFlag, args)` (`cmd/mindspec/next.go:403`) takes no pick parameter and its sole caller (`:75`) passes only `specFlag` and `args` — `--pick` is silently dropped in `--emit-only`. The *ordering* half of #187 fixed itself upstream in bd 1.1.0 (priority-first `bd ready` ordering; the claim path indexes the bd-returned order via `SelectWork`, so parity follows — verified at plan time). The *positional* half of the sibling #146 was fixed by spec 101 R1 (`SelectWorkByName`, `internal/next/select.go:42`, claims exactly the named bead or errors).
- **#146**: of its asks, positional-claim is fixed (spec 101), a release verb now exists (`mindspec release`, `cmd/mindspec/release.go` — strict 6-step reversal), and structured dependency wiring shipped in spec 097 R3 (`work_chunks` frontmatter with `id`/`depends_on` → `bd dep add`, cycle-validated at `internal/validate/plan.go:1055`, loud warning when the block is missing or unparseable, `internal/approve/plan.go:339-341`). What remains: the plan-order selection default, bd-stderr passthrough (`internal/bead/bdcli.go:443-455` runs `cmd.Output()` and wraps only "exit status 1" — the `exec.ExitError.Stderr` bytes that carry bd's actual diagnosis are dropped by every `%w` wrap, e.g. `internal/next/beads.go:54`), and the prose-`**Depends on**` residual disposed of below.

### The destructive-hint incident (#218), in full

A spec whose implementation reached `main` via an external GitHub PR (spec branch deleted, superseded by a git-native rebuild) could not be driven `review → idle`: (1) `impl approve` failed on raw `git merge-base … exit status 128` (`internal/approve/impl.go:332`) with no hint the branch was simply gone; (2) after manually recreating the branch, the orphan gate refused with `recovery: mindspec complete <bead>` (`implOrphanRefusal`, `internal/approve/impl.go:844` + `internal/lifecycle/orphans.go:70`); (3) that recommended merge's diff was −13,168 lines — the hint, followed verbatim, deletes the codebase. Resolution required manual git surgery. The existing hint-safety net does not cover this class: `guard.IsBannedRecoveryCommand` (`internal/guard/recovery.go:94-96`) bans only `bd update --metadata`. Spec 125 shipped exactly the primitives a state-aware hint needs — `lifecycle.FindLandedMerge`, `gitutil.ContentSubsumedOutcome`/`NetEffectLanded`, ancestry checks — so supersession- and net-deletion-awareness is a consumption problem, not a research problem.

## ADR Touchpoints

- [ADR-0023](../../adr/ADR-0023.md) — **APPLIED, no amendment**: the phase-derivation table *already* mandates mode `spec` for a created-but-unapproved spec ("No epic with matching `spec_num` → spec (draft)", `:98`); R1 makes the implementation faithful to it. Epic creation remains the spec-approval gate; beads/Dolt remain the single state authority — draft-spec detection reads the same on-disk shape (spec dir on its branch worktree) that GH #219/#222 already scan. If the plan finds the table needs a clarifying row for main-checkout-vs-spec-worktree visibility, that is a narrow clarification pre-drafted at plan time (122/123 precedent), not a semantic change.
- [ADR-0037](../../adr/ADR-0037-panel-gate-enforced-contract.md) — **AMENDED narrowly (§4), otherwise APPLIED**: §4 currently blocks whenever the ref moved off `reviewed_head_sha`, unconditionally. The amendment extends §5's existing ADR-0025 asymmetry ("artifact dirt is designed-for and never blocks at complete time") to the staleness rule: a delta since `reviewed_head_sha` whose *diff content* is confined to ADR-0025 artifact paths does not stale the verdicts. Confinement is established by diff content (`git diff <reviewed>..<tip> -- . ':!<artifact paths>'` empty), never by commit-message or path-list trust. Everything else in ADR-0037 — decision matrix, thresholds, dirty-tree rule, fail-open/fail-closed asymmetry — is untouched. Amendment pre-drafted at plan time, landed by the same bead that lands R2.
- [ADR-0041](../../adr/ADR-0041-gate-before-mutate.md) — **APPLIED, no amendment**: R2 is a direct application of the preflight→commit→reconcile contract to `complete`'s artifact-sync commit (the exact "auto-commit-before-gate / no-rollback shape that has bitten before" the ADR's context section names); R4's impl-approve branch-existence preflight is a preflight-leg fact; the adopt path is a forward-reconcile (re-derive from bd state, never a git rollback). Prefer refusing to act over acting and repairing, throughout.
- [ADR-0035](../../adr/ADR-0035-agent-error-contract.md) — **AMENDED narrowly, otherwise APPLIED**: every refusal this spec adds or edits keeps the named, copy-pastable final recovery line. The amendment adds a **recovery non-destructiveness clause**: a recovery command that would merge, delete, or overwrite work MUST be derived from verified current state (ancestry / supersession / net-effect evidence), never emitted as a static string; where the evidence says the action would destroy work, the recovery line MUST name the safe disposition instead. `Orphan.RecoveryCommand()` is the motivating instance; the clause governs the surfaces this spec touches and future recovery surfaces. Pre-drafted at plan time, landed by the same bead that lands R4a.
- [ADR-0025](../../adr/ADR-0025-jsonl-as-build-artifact.md) — unchanged, RESPECTED: the R2 content-confinement fact and the R3 dirt classification both reuse the single existing artifact classifier (the `next.CheckDirtyTree` path-set authority) — no second, divergent definition of "artifact path" is introduced.
- [ADR-0042](../../adr/ADR-0042-render-derivation-provenance.md) — unchanged, APPLIED: new messages that embed agent-writable content (offending path lists in the stale-SHA block, dirt path lists in the claim warning, bd stderr passthrough, branch names in adopt/orphan messages) render via `termsafe.Escape`/`idrender` per the house discipline.

## Requirements

Each requirement carries a hard falsifier. Requirements are grouped by failure mode. Diagnostic and guidance strings introduced or changed here are first-class outputs: their ACs pin what the messages *say and do* with a red-on-revert property, never that a string is non-empty (the W0 lesson: an existence check is not a truth check).

### Mode 1 — the verb must not lie about the state it produced

1. **R1 — State-after-verb honesty.** (GH #220.)
   (a) Mode derivation implements ADR-0023's declared table: a spec whose directory exists (draft `spec.md`, on its branch/worktree) with no matching epic derives mode **`spec`**, not `idle` — from inside the spec worktree, and from anywhere with `--spec <id>`. The `internal/resolve/resolve.go:59-61` epic-absent → `ModeIdle` shape is replaced by draft-spec detection using the same worktree-aware on-disk scan the #219/#222 fixes established.
   (b) `mindspec state show` from the **main** checkout while one or more draft specs exist does not report bare `{"mode": "idle"}`: it either resolves the single draft spec (mode `spec`, `activeSpec`, `specBranch`, and the worktree path to run from) or names the ambiguity — the operator can always tell "a spec exists in draft" from "nothing is active".
   (c) `spec create` emits **spec-mode** guidance for the spec it just created — naming the spec, the mode, and the worktree to `cd` into — never the idle-mode "No Active Work" block. The `--help` promise "sets state to spec mode" (`cmd/mindspec/spec.go:31`) becomes true as written.
   (d) **The class regression (worth more than any single fix): a per-verb state-agreement table.** For each mutating lifecycle verb — `spec create`, `spec approve`, `plan approve`, `next` (claim), `complete` (last bead), `impl approve` — an automated test drives the verb in a fixture and asserts that (i) `state show`'s `mode` afterwards equals the pinned expected mode (`spec`, `plan`, `implement`, `implement`, `review`, `idle` respectively) and (ii) the verb's own emitted state/guidance block agrees with that mode. The table is pinned in one place; adding a verb without adding a row fails the test.
   *Falsified if*: any fixture in the (d) table shows `state show` disagreeing with the verb's claimed post-state; or `spec create`'s emitted guidance contains the idle-mode block; or a draft spec with no epic still derives `idle` from its own worktree or via `--spec`.

### Mode 2 — the verb must not wedge with no way forward

2. **R2 — `complete` gates before it mutates, and a tracker-only delta never invalidates a passed panel.** (GH #186; ADR-0041 application + ADR-0037 §4 amendment.)
   (a) **Ordering**: `complete`'s fallible gates (doc-sync, ADR-divergence, panel) evaluate **before** the artifact-sync/tracker auto-commit lands, so a gate rejection leaves the branch tip exactly where the panel reviewed it (`reviewed_head_sha`), and a retry hits the **same** gate that rejected — never a new stale-SHA error caused by the tool's own commit. Refusal-before-mutation is the mechanism; no rollback path is introduced (ADR-0041: prefer refusing to act over acting and repairing).
   (b) **Content-confinement fact**: `panel.GateFacts` gains a fact reporting whether the delta `reviewed_head_sha..tip` is confined to ADR-0025 artifact paths, established by **diff content** (`git diff <reviewed>..<tip> -- . ':!<artifact paths>'` empty — the path set is the same single classifier authority `next.CheckDirtyTree` uses), never by commit subjects or path lists in tracker metadata. The stale-SHA rule treats an artifact-confined delta as non-invalidating (Allow, with a Warn naming the confinement); any delta touching a non-artifact path still **blocks**, and the block message names the offending paths (termsafe-escaped) alongside round, reviewed SHA, and tip — the operator can see *what* invalidated the review, not just that something did.
   (c) The #186 repro sequence — panel passes at `AAAA`, tracker dirt appears, `complete` fails doc-sync, retry with `--allow-doc-skew "<reason>"` — completes on the retry. No manual `reviewed_head_sha` repointing, no raw-git reset, ever required for this shape.
   *Falsified if*: a gate rejection leaves the branch tip advanced past `reviewed_head_sha`; or a retry after a gate rejection fails at a different gate than the one that rejected; or a delta confined to `.beads/issues.jsonl` blocks on stale-SHA; or a delta touching any non-artifact path passes the staleness rule; or confinement is judged from anything other than diff content.

3. **R3 — Claim and selection guards are proportionate, honest, and diagnosable.** (GH #179, #187, #146 residuals; the session-freshness gate is in scope as the same trust surface.)
   (a) **Worktree-creating claims are not blocked by dirt they will never touch**: when the claim creates a fresh bead worktree (the worktree-per-bead flow), user-authored dirt in the *invoking* checkout downgrades from a hard block to a **warning** that lists the dirt paths (termsafe-escaped) and states the claim will not touch them; the claim proceeds and the dirty files are left byte-identical. The hard block is **retained** for in-place (non-worktree) claims, where the bead branch is checked out into the invoking tree and dirt genuinely conflicts — ADR-0025's protective purpose is preserved where it applies.
   (b) **Both claim guards state their coverage truthfully.** The dirty-tree refusal (in-place mode) states that `--force` does **not** clear it and names what does (commit the WIP, or run from the active worktree — the existing `DirtyTreeFailure` steer); the session-freshness refusal keeps its full current strictness (hard error, `/clear` contract — **no relaxation**) and its text is pinned by test. The `--help` text documents which gate `--force` covers. Today an operator learns `--force`'s coverage only by trying it.
   (c) **`--emit-only` honors selection**: `mindspec next --pick N --emit-only` returns the N-th bead of the same ready list the claim path consumes; out-of-range N errors (`pick N out of range (1-M)`) instead of silently returning the first bead; `--pick` + positional remain mutually exclusive with the existing error. (#187's ordering half is fixed upstream in bd 1.1.0 and is re-verified, not re-fixed, at plan time.)
   (d) **Deterministic plan-order default**: when multiple beads are ready and no selector is given, `next` claims the lowest-bead-sequence-number bead under the epic (plan order) rather than list-first, and its output states that rule ("Defaulting to plan order (lowest bead number). Use --pick=N …"). Plan order is the authored DAG's intent; a priority-reordered `bd ready` list no longer silently changes which bead a bare `next` claims.
   (e) **bd failures surface bd's own diagnosis**: everywhere a bd shell-out failure is wrapped (the `bead.RunBD`/`tracedOutput` seam, `internal/bead/bdcli.go:443-455`), the wrapped error includes the captured `exec.ExitError.Stderr` content (termsafe-escaped, length-capped) — `bd ready for epic X failed: exit status 1` becomes `… exit status 1: Error 1105 … column "depends_on_id" could not be found …`. One seam-level fix covers every caller.
   *Falsified if*: a worktree-creating claim is still hard-blocked by unrelated invoking-tree user dirt, or the proceeding claim modifies any listed dirty file; or an in-place claim with user dirt no longer blocks; or the freshness gate is weakened in any way; or `--pick` under `--emit-only` returns a bead other than the N-th, or out-of-range returns a bead instead of an error; or a bare multi-ready `next` claims a bead other than the lowest sequence number; or a failing bd call surfaces only the bare exit status.

### Mode 3 — the verb's recovery guidance must never destroy work

4. **R4 — Recovery output is state-derived and non-destructive; an externally-merged spec has an audited path to `idle`.** (GH #218; ADR-0035 amendment; consumes the spec-121/125 landed/net-effect primitives.)
   (a) **`Orphan.RecoveryCommand()` becomes supersession- and net-deletion-aware.** Before any orphan refusal (impl-approve legs and `complete`'s orphan surfaces alike) recommends `mindspec complete <bead>`, the recommendation is derived from verified state: (i) a bead branch already an ancestor of the spec branch (or of `main`) → the hint names branch deletion, never a merge; (ii) a bead whose content evidence says it landed via another route (`lifecycle.FindLandedMerge` / `gitutil.ContentSubsumedOutcome` supersession evidence) → the hint names deletion of the stale branch plus the R4c adopt path, never a merge; (iii) a bead branch whose merge preview against the target is a large net deletion of content the branch never carried → the hint names inspection first (`git diff` command included) and states plainly that merging would delete landed work. A normal unmerged orphan — the common case — keeps `mindspec complete <bead>` unchanged. The evidence checks are read-only; where evidence is unavailable (git error), the hint degrades to inspection-first, never to the merge. The exact discriminator mechanics (which primitive, what floor for (iii)) are plan-level; the spec pins the behavior via the AC fixtures.
   (b) **Actionable spec-branch-missing preflight in `impl approve`.** Branch existence is resolved as a preflight fact (ADR-0041) before any merge-base computation: a missing spec branch produces a refusal that names the absent branch, states the likely cause ("the spec's content may have reached main outside the lifecycle"), and names the R4c adopt path as the recovery — never a raw `git merge-base … exit status 128` (`internal/approve/impl.go:332`).
   (c) **An audited adopt/reconcile path to `idle`.** An explicit, operator-invoked surface (naming — flag on `impl approve` vs. sibling verb — is plan-level, per the 125 precedent) transitions a `review`-state spec to `idle` and writes the finalize export **without any spec→main merge**, for the case where the spec's content reached `main` by another route. It is fail-closed and audited: it requires an operator-supplied reason, records an audit marker (reason, acting identity, timestamp, invoking operation) in epic metadata via the existing helpers (the spec-124 `--allow-not-ready` / 125 reattest pattern — detectable-by-inspection, not claimed tamper-proof); it refuses when the spec branch still exists (the normal path applies); it never runs implicitly. Orphaned closed beads encountered on the adopt path get the R4a state-aware disposition, not a merge demand.
   (d) **`complete`'s bead→spec merge gains a work-destruction preflight.** Before performing the merge, `complete` evaluates the same R4a evidence: a merge whose preview net-deletes previously-landed work (the #218 −13k-line shape) **refuses before any mutation**, names the evidence, and offers an audited override (`--allow-net-deletion "<reason>"`, recorded like `--allow-doc-skew`) for the honest-mass-deletion bead (a real cleanup/removal spec exists as a legitimate shape and must stay completable). *(Open Question 1 offers the gate a warn-only alternative; block+audited-override is the recommendation, matching the house pattern.)*
   *Falsified if*: any orphan refusal on the touched surfaces emits `mindspec complete <bead>` for a bead branch that is ancestor-merged, superseded, or mass-net-deleting; or following a printed recovery hint verbatim in the #218 fixture deletes landed work; or a normal unmerged orphan loses its converging `mindspec complete` hint; or a missing spec branch still surfaces a raw merge-base error; or the adopt path performs a spec→main merge, runs without an explicit reason, leaves no inspectable audit record, or proceeds while the spec branch exists; or `complete` merges the #218-shaped branch without refusal/override.

### Guidance

5. **R5 — Frozen-contract and external-merge guidance.** (GH #221.)
   (a) Idle-mode and review-mode instruct output gain the operative guidance: **new implementation work — including implementing a previously-frozen contract — starts a new spec** (`mindspec spec create`); a frozen *contract* spec does not obviate an *implementation* spec.
   (b) Review-mode instruct gains the external-merge note: when a spec's content already reached `main` outside the lifecycle, the path to `idle` is the R4c adopt surface — named by its real, shipped command string.
   (c) Both are pinned behaviorally: tests assert the operative sentences are present in the emitted instruct for those modes (red-on-revert), and an anti-drift check asserts the adopt command string the guidance names resolves to a registered command — the guidance can never advertise a verb that does not exist.
   *Falsified if*: idle- or review-mode instruct lacks the operative sentences; or the named adopt command does not exist as typed; or the test asserts mere non-emptiness rather than the operative content.

### Evidence

6. **R6 — Regression evidence, CI-hermetic.** Every fixed class is pinned by an automated test that is RED on today's `main` (or on fix-revert) and runs in CI's bd-less `go test -short ./...` lane, per the spec-119 no-skip-gating convention: bd-touching legs run through the existing injectable seams (`runBDFn`, the executor seams, `checkDirtyTreeFn`, gate-fact construction) backed hermetically; no new gating test may skip-when-bd-missing; a test that genuinely requires a real `bd` FATALs rather than skips when its declared environment lacks it. The R1(d) per-verb agreement table runs seam-hermetic in CI; a full-stack bd-backed variant may additionally exist for the local lane but is not the gating copy. `internal/harness` and `internal/instruct` are pre-existing RED; new tests must not hide behind either.
   *Falsified if*: any fixed class lacks a RED-today (or red-on-revert) test; or a new gating test silently skips in the bd-less lane.

## Scope

### In Scope

- `internal/resolve/resolve.go`, `internal/phase/**`, `cmd/mindspec/state.go`, `cmd/mindspec/spec.go`, `internal/instruct/**` — draft-spec mode derivation, state show honesty, spec-create spec-mode guidance, per-verb agreement regression (R1).
- `internal/complete/complete.go` (gate-vs-artifact-commit ordering), `internal/panel/gate.go` (+ the GateFacts construction sites) — content-confinement fact, stale-SHA message; the narrow ADR-0037 §4 amendment (R2).
- `cmd/mindspec/next.go`, `internal/next/guard.go`, `internal/next/select.go` — worktree-creating-claim dirt downgrade, guard-coverage honesty, emit-only pick, plan-order default (R3a-d).
- `internal/bead/bdcli.go` (the `tracedOutput`/error-wrap seam) — bd stderr passthrough (R3e).
- `internal/lifecycle/orphans.go` (+ its impl-approve and complete consumers), `internal/approve/impl.go` — state-aware `RecoveryCommand`, spec-branch-missing preflight, adopt path, `complete` merge preflight + `--allow-net-deletion`; the narrow ADR-0035 amendment (R4). Read-only consumption of `internal/lifecycle/landed.go` / `internal/gitutil/neteffect.go` primitives.
- `internal/instruct/**` + the relevant skill/doc surfaces — frozen-contract and external-merge guidance (R5).
- Regression tests per R6 across the packages above.

A natural decomposition is **five beads**: (1) R1 — state honesty + the per-verb agreement table; (2) R2 — complete gate ordering + content-confinement + ADR-0037 §4 amendment; (3) R3 — claim guards, selection, emit-only pick, bd stderr (one seam-cluster: `cmd/mindspec/next.go` + `internal/next` + `internal/bead`); (4) R4a/b/d — state-aware recovery hints, impl-approve preflight, complete merge preflight + ADR-0035 amendment; (5) R4c + R5 — adopt path + the guidance that references it (naturally coupled: the guidance must name the shipped surface). Beads 4 and 5 both touch `internal/approve`; the plan sequences 5 after 4. If the plan gate judges bead 3 or bead 4 oversized, the honest response is a **split to six** (3 → guards vs. selection/diagnostics, or 4 → hints vs. preflights), never compression.

## Non-Goals

- **No weakening of any gate.** R2 narrows *one input* (tracker-only deltas) of the staleness rule by diff-content evidence; every other block, including the freshness gate and the in-place dirt block, keeps full strictness. No new bypass lacks an audit trail.
- **No new lifecycle authority.** The adopt path transitions state through the existing bd/epic machinery with an audit marker; it grants no consumer the right to bypass panels, close beads, or merge branches.
- **No git rollback machinery.** R2 is refusal-before-mutation, not commit-then-revert (ADR-0041 posture).
- **No heuristic revert/supersession detection beyond the shipped primitives.** R4 consumes `FindLandedMerge`/`ContentSubsumedOutcome`/ancestry as spec 121/125 shipped them, inheriting their stated residuals; it does not extend their discrimination.
- **No cryptographically tamper-proof audit** — adopt/override markers are bd-metadata, detectable-by-inspection (the 124/125 posture), claimed as exactly that.
- **No TUI/output-format redesign** — message *content* is pinned where trust requires it; formatting conventions stay as they are.
