# Spec 127-lifecycle-verb-trustworthiness: Destructive Recovery and the Externally-Merged Spec (the #218 cluster)

## Goal

No lifecycle verb ever prints a recovery instruction that would destroy work, no lifecycle merge executes without work-destruction evidence being consulted, and a spec whose content reached `main` outside the lifecycle has a first-class, audited, merge-free path to its terminal state.

**Provenance of this revision.** The nine-slot spec gate returned 9/9 REQUEST_CHANGES on the draft. Six of nine slots judged the draft's five-bead, seven-issue scope over-compressed (O3 measured ~10 independently-reviewable deliverables), and the gate split the spec. **Spec 127 keeps the GH #218 cluster end-to-end plus the destructive-recovery class it belongs to; everything else — state honesty (#220), `complete` gate ordering (#186), claim/selection (#179, #187, #146), and mode guidance (#221) — moves to follow-on spec 128** (filed separately; this spec claims closure of none of them, and their draft-127 requirement text does not survive into this revision). The split boundary is the #218 cluster, not the failure-mode boundary: the recovery hints this spec ships must name the adopt path this spec also ships, and a mode-boundary split would put that dependency across two specs.

**Revision 3, after the six-slot re-gate (6/6 REQUEST_CHANGES on revision 2).** Two mechanisms of revision 2 are *replaced*, not repaired, per the re-gate's convergent findings: (1) AC-3's execute-the-emitted-recovery-line assertion was self-contradictory on its own guard leg, had no R6-satisfying venue, and — decisively — made the test harness the executor of whatever a regressed derivation emits (O2-r2-1/-2, O3-r2-8, S3-r2-2/-3); it is replaced by the **outcome oracle** (AC-3), which never executes an emitted string. (2) The `:1688`/`:1721` conflict-recovery allowlist rationale is **overturned** (C2-r2-1, adjudicated over F3's reachability argument): the preflight gated the product's merge attempt A; the printed command starts a *new* merge B, run by hand through raw git, which the preflight never evaluates — reachability-of-the-emitter and safety-of-the-emitted-command are different questions. Those two lines are **converted** through the evidence-carrying constructor with OID pinning (R5d), not registered. Both dependency inversions are now fixed by construction: the shared predicate lands first (bead 1) and the adopt surface before every hint that names it (bead 3 < bead 4).

**Why this half ships first, inverting the draft's order:** this class is *active work destruction*. In the #218 incident the tool's own printed hint, followed verbatim, would have merged a stale branch whose diff was −13,168 lines. And the class has a live, previously-unnamed instance shipped today (C2-2): plan re-approval sees a closed child, explicitly admits it may be completed work, and still emits `bd delete <id> --force` as its sole machine-greppable recovery command, gated by no verified fact (`internal/approve/plan.go:820-825`). A refusal that is wrong is costly; a recovery hint that is wrong is executed with the operator's guard down, because the tool told them to.

**Target outcome** (pinned to what the ACs deliver — not "structurally impossible", per F1-10/S3-9): after this spec, on every enumerated surface, (a) a destructive-class command appearing anywhere in a lifecycle diagnostic — recovery line, message body, or labeled choice block — can only be produced through an evidence-carrying constructor whose destructive variants cannot be invoked without an evidence result, and a newly introduced static destructive command is red at development time (the repo-wide convention scan); (b) every lifecycle merge producer consults one mandatory work-destruction preflight before mutating, with a block + audited `--allow-net-deletion "<reason>"` override; (c) an externally-merged spec reaches its terminal state through an audited, evidence-gated, merge-free adopt surface that the branch-missing refusal names; (d) `mindspec complete <bead>` remains the converging common-case hint everywhere it is correct — it is made safe upstream by (b), not banned syntactically; (e) where the *correct* recovery is itself destructive (the #218 stale-branch deletion), the hint is emitted **with the evidence that proves it right** — this spec does not merely avoid destructive hints, it proves the ones it must emit.

## Background

All citations verified in this worktree (branch `spec/127-lifecycle-verb-trustworthiness`, forked from `main` at `09f62bd9`, v0.14.0). GH #218 is OPEN.

### The incident (#218), in full — including its composite state

A spec whose implementation reached `main` via an external GitHub PR (spec branch deleted, superseded by a git-native rebuild) could not be driven `review → idle`: (1) `impl approve` failed on a raw `git merge-base … exit status 128` (`internal/approve/impl.go:330-332`) with no hint the branch was simply gone; (2) after the operator manually recreated the branch at `main`, the orphan gate refused with `recovery: mindspec complete <bead>` (`implOrphanRefusal`, `internal/approve/impl.go:842-851` + `internal/lifecycle/orphans.go:70`); (3) that recommended merge's diff was **−13,168 lines** — the hint, followed verbatim, deletes most of the codebase.

**The state the incident occurred in is composite** (O1-r2-3): a `review`-state spec with its branch deleted-then-recreated, *plus a closed bead (`autonomous-agents-078.3`) whose stale bead branch still existed* — the orphan is what produced steps 2 and 3, and the documented resolution was `git branch -D` on it, then re-run `impl approve`. Two design consequences: the incident's step (2) means "spec branch missing" and "spec branch present but stale" are *both* observed shapes (F3-1), and **the correct recovery in the incident state is itself destructive** — delete the stale bead branch, never merge it. So this spec's obligation is stronger than avoiding destructive hints: it must *emit* a destructive command in that state and *prove* it is the right one (AC-2(viii), AC-3(i)).

### The live class, inventoried

The gate's destruction-surface audit (C2-1, C2-2, C2-3, F3-2, O3-r2-3) established that the draft's "state-derived recovery" rule was a slogan covering a fraction of the class. The full inventory at this base:

No content change to the skills is required at this base; the sweep pins the family so a future skill teaching `git branch -D` or a raw merge is convention-red (AC-10(iii)).

## Requirements

Diagnostic and guidance strings introduced or changed here are first-class outputs: their ACs pin what the messages *say and do* — the hint's **claimed outcome is independently proven by the outcome oracle** (AC-3's mechanism: ground truth re-derived through pinned non-mutating probes, never by executing an emitted string) — with a red-on-revert property, never that a string is non-empty (the W0 lesson; O2-7's sharpening, as corrected by the re-gate: the assertion that falsifies the #218 class is proving the hinted action's *outcome* against the same evidence the hint was derived from, S3-r2-3).

### The shared work-destruction predicate (bead 1 — the root of the dependency graph)

For a candidate merge of branch `B` into target `T`, the evidence classes are pinned at spec level; there is **no numeric floor or ratio at spec level**:

1. **Ancestry** — `B` is already an ancestor of `T` (or of `main`): there is nothing to merge; the safe disposition is branch deletion / no-op.
2. **Supersession** — `B`'s content already landed in `T` or `main` via another route (`lifecycle.FindLandedMerge`, `gitutil.ContentSubsumedOutcome`, `gitutil.NetEffectLanded`): merging the stale snapshot would regress landed work.
3. **Stale-deletion** — the merge preview deletes content present in `T` that `B`'s own authored range (`merge-base(B,T)..B`) never carried: the deletions are artifacts of `B`'s staleness, not authored changes. **"Content the branch never carried" is part of the predicate** (F1-2, ruled): an honest cleanup bead authors its deletions inside its own range and passes clean — no override toll; so does a large rename/move.

**The predicate returns a closed, named outcome set** (enum/variant type: ancestor, superseded, stale-deletion, clean, evidence-error), and every consumer switches over it exhaustively — a new variant without a fixture in every consumer's table is red at development time (O2-r2-4). **Per-consumer outcomes are pinned** (F3-r2-1): at the R4 *merge preflight*, `ancestor` proceeds as a no-op — the documented post-conflict recovery flow depends on the re-run converging via ancestry (`mindspec_executor.go:1649-1653`); `superseded` and `stale-deletion` refuse; at the R2 *hint derivation*, `ancestor` yields the deletion hint. The plan chooses mechanics (which primitive answers which class, read-only throughout) and MAY add a numeric leg only as a *secondary, conservative tripwire* (F3-5); the AC-8 must-pass fixtures (large rename; honest cleanup; post-conflict re-run) make a bare deleted-line floor unimplementable. **Evidence unavailable or uncomputable (git error, missing ref, inconclusive primitives): absence of evidence is never treated as safety.** Preflights refuse fail-closed with a named retryable error, the audited override remaining available (F3-3); hints degrade to inspection-first, never to the destructive action (S3-9). Every predicate consumer below states its evidence-unavailable behaviour explicitly (O2-2's generalization).

### R1 — An audited, merge-free adopt path

For the case where a `review`-state spec's content reached `main` by another route:
(a) An explicit, operator-invoked surface (naming — flag on `impl approve` vs. sibling verb — is plan-level per the 125 precedent; every AC that names the invocation resolves it *in full, including flags*, per AC-11) transitions the spec to its terminal state: closes the epic, writes the finalize export, records an audit marker (reason, acting identity, timestamp, invoking operation) via the existing helpers (the 124 `--allow-not-ready` / 125 reattest pattern — detectable-by-inspection, not claimed tamper-proof). It performs **no spec→main merge**; any main-side delta is confined to the finalize-export artifact.
(b) **Positive landed evidence is required** (C1-5, F1-4): the surface consults the shared predicate's supersession leg. **The evidence sources for the deleted-branch shape are pinned** (O3-r2-2 — the 125 primitives are all ref-keyed, so "consumption not research" holds only where a ref survives): (i) a surviving remote ref for the spec branch (e.g. `origin/<specBranch>`), evaluated directly; (ii) the epic's surviving bead branches, each evaluated per-branch — every surviving bead branch landed/subsumed in `main` is positive evidence; any negative or stale result is negative evidence for the whole. When no ref-bearing source exists, or sources conflict, **verified adopt is unavailable by design**: the refusal mutates nothing and names inspection plus the attestation escape in (c). A deleted branch is not proof of an external merge, and this spec ships no branch-less landing oracle.
(c) **Attestation escape**: a distinct, explicit flag lets the operator proceed when evidence cannot be computed; its audit marker records in its own wording that **landing was NOT verified and was operator-attested** (C1-5's alternative, adopted as the escape rather than the default). In the #218 incident's own deleted-and-rebuilt shape — where the surviving bead branch is *stale*, i.e. negative evidence — this is the honest terminal route, and the closes-map says so.
(d) **Branch-present refusals are evidence-aware** (F1-3, F3-1): with the spec branch present and *current* (not superseded), the refusal names the normal path; with the branch present but *stale* per the predicate (the #218 step-2 recreated-branch shape), the refusal names inspection + stale-branch deletion + adopt rerun — never a bare "the normal path applies", because in that state the normal path is the destructive merge.
(e) **Never implicit**: the only caller of the adopt entrypoint is its own registered command handler, pinned by a call-site enumeration test (O2-8's rewrite of the untestable negative universal).
(f) **No third terminal shape**: adopt's durable post-state (epic closed, `mindspec_phase=done`, finalize export present) is asserted *equal to a normal `impl approve`'s* in a comparison fixture, so the surface cannot invent a divergent done-state (C1-3's ambient-vs-targeted table question travels to spec 128; durable markers are the observable here).
(g) **The composite incident state is a first-class fixture** (O1-r2-3): adopt invoked with a closed bead's stale bead branch still present refuses before mutation, and its refusal renders the R2-derived hint — inspection first, evidence-proven stale-branch deletion, adopt rerun — never `mindspec complete`. Adopt's orphan-present refusal joins R2(a)'s emitter enumeration. (Until bead 4 lands the derivation, bead 3's interim orphan-present refusal is inspection-first with no destructive command — stated in the Decomposition so the interim state is priced, not discovered.)
*Falsified if*: adopt performs any spec→main merge; proceeds without a reason; proceeds with negative/absent evidence and no attestation; its audit record omits or blurs the verified-vs-attested distinction; the branch-present-stale refusal steers to the normal path; the orphan-present state draws a `mindspec complete` hint; any non-explicit surface triggers it.

### R2 — Orphan recovery hints are state-derived, through one constructor

(a) **Single derivation**: all four production consumers of the orphan hint (`complete.go:520`/`:552`, `impl.go:850`, `orphaned_beads.go:100`) render it from **one derivation function that takes a predicate outcome and cannot be called without one** (O2-7's structural leg), returning the closed outcome type plus its rendered lines. A call-site anti-drift test enumerates every emitter that renders an orphan recovery line — including R1(g)'s adopt refusal — so a new surface cannot bypass the evidence check.
(b) **Pinned outcomes, one per predicate class, mapped 1:1 onto AC-3's legs** (O1-r2-1, O2-r2-4): bead branch **ancestor of `main` but not of the spec branch** → the hint names branch deletion, never a merge (this — not ancestor-of-spec — is the reachable case: an ancestor-of-spec branch never becomes an `Orphan` at all, `orphans.go:55-57` and `:181-190`; stated so nobody builds the dead fixture — F3-4/O3-11); **superseded / landed via another route** → the hint names stale-branch deletion plus the R1 adopt path by its full invocation; **stale-deletion shape** → the hint names inspection first (a concrete `git diff` command included) and states plainly that merging would delete landed work; **normal unmerged orphan** → the hint remains exactly `mindspec complete <bead>`, unchanged — the converging common case, safe by construction once R4 preflights the merge it triggers; **evidence unavailable/error** → inspection-first, never the merge (S3-9's leg). **Destructive hints carry their proof** (Target outcome (e)): a deletion hint states the evidence class that licenses it, and when the doomed branch carries commits unreachable from `main`/spec, the hint says so and names preservation first (e.g. tag before delete).
(c) **The doctor FixFunc is gated by the same outcome** (O3-r2-3): `orphaned_beads.go`'s `FixFunc` is populated **only** for the `normal unmerged` outcome (where `mindspec complete` is the correct action, itself R4-preflighted); for ancestor/superseded/stale-deletion/evidence-error outcomes the Check carries no FixFunc, so `doctor --fix` mutates nothing in those states. The verb's output and the verb's action derive from one value and cannot disagree.
(d) **Sweep scoping** (O3-9): `StaleOpenBead` (`stale_open.go:67`) and `FinalizeOrphan` (`finalize_orphans.go:92`) hints are **out** of the derivation change — the former is correct (reconcile convergence, `complete.go:867-875`), the latter already state-derived — and both are registered in R5's convention with those rationales.
*Falsified if*: any consumer emits a merge-shaped hint for an ancestor/superseded/stale-deletion branch; the derivation is callable without a predicate outcome; an orphan-hint emitter exists outside the enumeration; `doctor --fix` mutates anything in a non-normal outcome state; the outcome oracle disproves any leg's claimed outcome (AC-3); the common-case hint changes.

### R3 — Approve-surface refusals are gated by verified facts

(a) **Branch-missing preflight in `impl approve`** (the #218 step-1 wedge): branch existence is resolved as a preflight fact before any merge-base or other git plumbing touches the branch name; a missing spec branch produces a refusal naming the absent branch, the external-merge likelihood, and the R1 adopt path by its full invocation. No raw `exit status 128`, and no wrapped `*exec.ExitError` escapes to the operator (O2-8's positive form). **Branch existence indeterminate (probe error) is its own leg** (O2-r2-8): a fail-closed retryable refusal, distinct in wording from the branch-absent refusal, that does **not** name adopt as the disposition — "could not determine" never becomes "absent".
(b) **Branch-present-but-stale**: `impl approve`'s finalize merge is guarded by R4's preflight (the spec→main producer), so a recreated/stale spec branch refuses before mutation instead of merging the stale snapshot (F3-1's fixture). *Delivered by bead 6 with R4; stated here for requirement completeness and assigned there in the Decomposition (O3-r2-5).*
(c) **Plan re-approve closed-child provenance** (C2-2 — the live instance): the closed case at `plan.go:820-825` emits `bd delete <id> --force` **only when durable state positively establishes partial/interrupted provenance** (the mechanics — e.g. absence of a bead branch, absence of landed-merge evidence, supersede-run markers — are plan-level; the direction is pinned: deletion requires positive provenance). When evidence indicates completed work, **or is ambiguous or unavailable**, the refusal preserves the record and names inspection/reconciliation instead. **The provenance evidence is resolved in the `ApprovePlan` preflight — where the children are already resolved — and passed into `checkExistingBeadsSafety` as a value**, preserving that function's documented no-I/O purity; the check itself acquires nothing, so AC-6 stays a pure, hermetic table test (S3-r2-5). The model is the sibling site `plan.go:715-728`, whose deletion hint carries by-construction provenance. `bd delete … --force` joins R5's destructive classifier, and **both plan.go sites route through the constructor** — neither may take the allowlist route (O1-r2-6/C2-r2-2: the final allowlist is exactly pinned, and these are not in it).
*Falsified if*: a missing branch still surfaces a merge-base error; an indeterminate existence probe is treated as absence or routes to adopt; a stale recreated spec branch reaches the finalize merge unguarded; a closed child with completed-work or ambiguous evidence still draws a `bd delete --force` hint; an evidence-free deletion hint passes the convention scan.

### R4 — One work-destruction preflight, every merge producer

(a) A single mandatory preflight API evaluates the shared predicate **before any lifecycle merge mutation**, consulted by all three producers: `CompleteBead`'s bead→spec merge (`mindspec_executor.go:411`), `FinalizeEpic`'s bead→spec auto-merge (`:703`), and the direct spec→main merge (`:916`). **Siting is pinned** (O1-r2-2): the work-destruction facts are resolved in each verb's ADR-0041 §1 preflight phase — for `complete`, before the step-2.5/3 artifact-materialization subphase — and this is sufficient because the destruction classes are properties of the branch's *committed history*, not of the pending commit: commits authored in the current run fall inside the authored range by construction, so they cannot create a stale-deletion the preflight missed, and new commits cannot make a branch *more* superseded. The producer-site consultation is a backstop assertion that the preflight-phase evaluation ran for this merge input — the user-facing refusal fires only in the preflight phase, so **no R4 refusal leaves a tool-generated commit on the bead branch** (the #186 stale-SHA wedge is not re-armed by this spec). On the direct spec→main leg, the preflight is **hoisted above the cleanup block** (F3-r2-3; the `guardMergeLayout` precedent at `mindspec_executor.go:845-857`) — a refusal fires before any worktree or branch removal. (b) A refusal happens **before mutation** (observables pinned in the AC preamble), names the evidence, and offers the audited override `--allow-net-deletion "<reason>"`, recorded like `--allow-doc-skew` on epic metadata **and registered in the escape-hatch friction registry** — `cmd/mindspec/selfemit.go`'s `escapeHatchFlags` and `internal/redact`'s `EscapeHatchTokens` — so repeated overrides are visible to friction reporting (O3-10). **Its position in `detectFriction`'s deterministic first-flag-wins order is stated in code** (S3-r2-7: one admission per entry; when several hatches are bound in one run only the first in order is recorded — AC-7(ii)'s fixture therefore binds only this flag).
