# Spec 127-lifecycle-verb-trustworthiness: Destructive Recovery and the Externally-Merged Spec (the #218 cluster)

## Goal

No lifecycle verb ever prints a recovery instruction that would destroy work, no lifecycle merge executes without work-destruction evidence being consulted, and a spec whose content reached `main` outside the lifecycle has a first-class, audited, merge-free path to its terminal state.

**Provenance of this revision.** The nine-slot spec gate returned 9/9 REQUEST_CHANGES on the draft. Six of nine slots judged the draft's five-bead, seven-issue scope over-compressed (O3 measured ~10 independently-reviewable deliverables), and the gate split the spec. **Spec 127 keeps the GH #218 cluster end-to-end plus the destructive-recovery class it belongs to; everything else — state honesty (#220), `complete` gate ordering (#186), claim/selection (#179, #187, #146), and mode guidance (#221) — moves to follow-on spec 128** (filed separately; this spec claims closure of none of them, and their draft-127 requirement text does not survive into this revision). The split boundary is the #218 cluster, not the failure-mode boundary: the recovery hints this spec ships must name the adopt path this spec also ships, and a mode-boundary split would put that dependency across two specs. The gate's dependency inversion (O3-1: the draft had hints naming an adopt surface a *later* bead would register) is fixed by construction — the adopt surface lands first.

**Why this half ships first, inverting the draft's order:** this class is *active work destruction*. In the #218 incident the tool's own printed hint, followed verbatim, would have merged a stale branch whose diff was −13,168 lines. And the class has a live, previously-unnamed instance shipped today (C2-2): plan re-approval sees a closed child, explicitly admits it may be completed work, and still emits `bd delete <id> --force` as its sole machine-greppable recovery command, gated by no verified fact (`internal/approve/plan.go:820-825`). A refusal that is wrong is costly; a recovery hint that is wrong is executed with the operator's guard down, because the tool told them to.

**Target outcome** (pinned to what the ACs deliver — not "structurally impossible", per F1-10/S3-9): after this spec, on every enumerated surface, (a) a recovery line naming a destructive-class action can only be produced through an evidence-carrying constructor whose destructive variants cannot be invoked without an evidence result, and a newly introduced static destructive hint is red at development time (convention test); (b) every lifecycle merge producer consults one mandatory work-destruction preflight before mutating, with a block + audited `--allow-net-deletion "<reason>"` override; (c) an externally-merged spec reaches its terminal state through an audited, evidence-gated, merge-free adopt surface that the branch-missing refusal names; (d) `mindspec complete <bead>` remains the converging common-case hint everywhere it is correct — it is made safe upstream by (b), not banned syntactically.

## Background

All citations verified in this worktree (branch `spec/127-lifecycle-verb-trustworthiness`, forked from `main` at `09f62bd9`, v0.14.0). GH #218 is OPEN.

### The incident (#218), in full

A spec whose implementation reached `main` via an external GitHub PR (spec branch deleted, superseded by a git-native rebuild) could not be driven `review → idle`: (1) `impl approve` failed on a raw `git merge-base … exit status 128` (`internal/approve/impl.go:330-332`) with no hint the branch was simply gone; (2) after the operator manually recreated the branch, the orphan gate refused with `recovery: mindspec complete <bead>` (`implOrphanRefusal`, `internal/approve/impl.go:842-851` + `internal/lifecycle/orphans.go:70`); (3) that recommended merge's diff was **−13,168 lines** — the hint, followed verbatim, deletes most of the codebase. Resolution required manual git surgery. Note the incident's step (2) means the "spec branch missing" and "spec branch present but stale" variants are *both* observed shapes: guarding only the missing-branch leg steers the operator into an unguarded merge of the recreated stale branch (F3-1).

### The live class, inventoried

The gate's destruction-surface audit (C2-1, C2-2, C2-3, F3-2) established that the draft's "state-derived recovery" rule was a slogan covering one third of the class. The full inventory at this base:

- **Static orphan hint**: `Orphan.RecoveryCommand()` (`internal/lifecycle/orphans.go:70`) unconditionally returns `mindspec complete <bead>`. Four production consumers render it: `internal/complete/complete.go:520` and `:552`, `internal/approve/impl.go:850`, and `internal/doctor/orphaned_beads.go:100` (`doctor` was absent from the draft's Impacted Domains — O3-9).
- **Unguarded deletion hint**: `checkExistingBeadsSafety`'s closed-child case (`internal/approve/plan.go:820-825`) admits the bead "is either completed work … a leftover from a failed partial bead create, OR a leftover from an interrupted supersede-close", then unconditionally emits `bd delete <id> --force`. The correct form already exists 100 lines up: the partial-create failure at `plan.go:715-728` hints `bd delete … --force` for IDs that are *by construction* the partial set that very run created — a deletion hint carrying its own provenance.
- **Three merge producers, one guarded by the draft**: `CompleteBead`'s bead→spec `gitutil.MergeInto` (`internal/executor/mindspec_executor.go:411`), `FinalizeEpic`'s bead→spec auto-merge `MergeInto` (`:703`), and the direct spec→main `gitutil.MergeBranch` (`:916`). None consults supersession/net-effect evidence; the existing guards are layout-regression (`guardMergeLayout`), allow-set membership, and plain ancestry.
- **Static raw-merge recovery lines**: the post-conflict-abort guidance emits `git merge --no-ff -m "Merge <bead>" <bead>` (`mindspec_executor.go:1688`) and `git merge --no-ff <specBranch>` into main (`:1721`) — deliberate spec-092/125 design, but currently indistinguishable, to any enforcement, from a careless static merge hint.
- **Destructive discard inside a pasteable recovery**: `cmd/mindspec/release.go:257` embeds "or discard them by re-running with `mindspec release <bead> --force`" inside the single recovery line.
- **Shipped agent guidance teaching the bypass**: `.claude/agents/spec-orchestrator.md:163-175` instructs `git stash push`, raw `git merge --no-ff bead/<id>`, `git worktree remove … --force`, `git branch -D bead/<id>`, and raw `bd update <epic-id> --metadata=…` — the last being the exact command family the runtime ban rejects.
- **The enforcement that exists**: `guard.FormatFailure` (`internal/guard/recovery.go:46-69`) panics on banned commands; `IsBannedRecoveryCommand` (`:94-96`) has **exactly one entry** (`bd update` + `--metadata`); `internal/guard/recovery_convention_test.go` (Req 21) walks every guard-failure constructor but enforces only final-line *shape*, not derivation.
- **Why a syntactic ban cannot express this class**: `mindspec complete <bead>` is itself the mandated common-case hint, and the raw-merge conflict-recovery lines are deliberate design. Enforcement must therefore be *contextual* — derivation through an evidence-carrying constructor plus a registered, rationale-carrying allowlist — which is R5's job to design, not prose's job to wish for (F3-2).

**Correct-by-design adjacent sites that scope the sweep** (named so the sweep cannot break them — O3-9): `StaleOpenBead.RecoveryCommand` (`internal/lifecycle/stale_open.go:67`) hints `mindspec complete`, which is *correct* — complete's reconcile path converges an already-landed bead (`internal/complete/complete.go:867-875`); `FinalizeOrphan.RecoveryCommand` (`internal/lifecycle/finalize_orphans.go:92`) is already state-derived (a `Kind` switch yielding PR/pull/impl-approve guidance, no raw merge). The house fail-closed precedent for evidence errors is `FinalizeEpic`'s ancestry-error handling (`mindspec_executor.go:640-659`, ADR-0041 §2(ii)): refuse recoverably, mutate nothing, preserve the branch.

**Shipped primitives**: spec 125 shipped exactly the evidence a state-aware hint and preflight need — `lifecycle.FindLandedMerge` (`internal/lifecycle/landed.go:424`), `gitutil.ContentSubsumedOutcome` (`internal/gitutil/neteffect.go:251`), `gitutil.NetEffectLanded` (`:442`), and the ancestry checks. This is a consumption problem, not a research problem.

## Requirements

Diagnostic and guidance strings introduced or changed here are first-class outputs: their ACs pin what the messages *say and do* — including executing the printed hints and asserting the result — with a red-on-revert property, never that a string is non-empty (the W0 lesson, and O2-7's sharpening of it: the one assertion that falsifies the #218 class end-to-end is *running the emitted recovery line*).

### The shared work-destruction predicate (OQ-2 of the draft, resolved here per the gate ruling)

For a candidate merge of branch `B` into target `T`, the evidence classes are pinned at spec level; there is **no numeric floor or ratio at spec level**:

1. **Ancestry** — `B` is already an ancestor of `T` (or of `main`): there is nothing to merge; the safe disposition is branch deletion / no-op.
2. **Supersession** — `B`'s content already landed in `T` or `main` via another route (`lifecycle.FindLandedMerge`, `gitutil.ContentSubsumedOutcome`, `gitutil.NetEffectLanded`): merging the stale snapshot would regress landed work.
3. **Stale-deletion** — the merge preview deletes content present in `T` that `B`'s own authored range (`merge-base(B,T)..B`) never carried: the deletions are artifacts of `B`'s staleness, not authored changes. **"Content the branch never carried" is part of the predicate** (F1-2, ruled): an honest cleanup bead authors its deletions inside its own range and passes clean — no override toll; so does a large rename/move.

The plan chooses mechanics (which primitive answers which class, read-only throughout) and MAY add a numeric leg only as a *secondary, conservative tripwire* (F3-5); the AC-8 must-pass fixtures (large rename; honest cleanup) make a bare deleted-line floor unimplementable. **Evidence unavailable or uncomputable (git error, missing ref, inconclusive primitives): absence of evidence is never treated as safety.** Preflights refuse fail-closed with a named retryable error, the audited override remaining available (F3-3); hints degrade to inspection-first, never to the destructive action (S3-9). Every predicate consumer below states its evidence-unavailable behaviour explicitly (O2-2's generalization).

### R1 — An audited, merge-free adopt path (ships first)

For the case where a `review`-state spec's content reached `main` by another route:
(a) An explicit, operator-invoked surface (naming — flag on `impl approve` vs. sibling verb — is plan-level per the 125 precedent; every AC that names the invocation resolves it *in full, including flags*, per AC-11) transitions the spec to its terminal state: closes the epic, writes the finalize export, records an audit marker (reason, acting identity, timestamp, invoking operation) via the existing helpers (the 124 `--allow-not-ready` / 125 reattest pattern — detectable-by-inspection, not claimed tamper-proof). It performs **no spec→main merge**; any main-side delta is confined to the finalize-export artifact.
(b) **Positive landed evidence is required** (C1-5, F1-4): the surface consults the shared predicate's supersession leg; when evidence is negative or unavailable it refuses — mutating nothing — and names inspection plus the attestation escape in (c). A deleted branch is not proof of an external merge.
(c) **Attestation escape**: a distinct, explicit flag lets the operator proceed when evidence cannot be computed; its audit marker records in its own wording that **landing was NOT verified and was operator-attested** (C1-5's alternative, adopted as the escape rather than the default).
(d) **Branch-present refusals are evidence-aware** (F1-3, F3-1): with the spec branch present and *current* (not superseded), the refusal names the normal path; with the branch present but *stale* per the predicate (the #218 step-2 recreated-branch shape), the refusal names inspection + stale-branch deletion + adopt rerun — never a bare "the normal path applies", because in that state the normal path is the destructive merge.
(e) **Never implicit**: the only caller of the adopt entrypoint is its own registered command handler, pinned by a call-site enumeration test (O2-8's rewrite of the untestable negative universal).
(f) **No third terminal shape**: adopt's durable post-state (epic closed, `mindspec_phase=done`, finalize export present) is asserted *equal to a normal `impl approve`'s* in a comparison fixture, so the surface cannot invent a divergent done-state (C1-3's ambient-vs-targeted table question travels to spec 128; durable markers are the observable here).
*Falsified if*: adopt performs any spec→main merge; proceeds without a reason; proceeds with negative/absent evidence and no attestation; its audit record omits or blurs the verified-vs-attested distinction; the branch-present-stale refusal steers to the normal path; any non-explicit surface triggers it.

### R2 — Orphan recovery hints are state-derived, through one constructor

(a) **Single derivation**: all four production consumers of the orphan hint (`complete.go:520`/`:552`, `impl.go:850`, `orphaned_beads.go:100`) render it from **one derivation function that takes an evidence result and cannot be called without one** (O2-7's structural leg). A call-site anti-drift test enumerates every emitter that renders an orphan recovery line, so a new surface cannot bypass the evidence check.
(b) **Pinned outcomes** by evidence class: bead branch **ancestor of `main` but not of the spec branch** → the hint names branch deletion, never a merge (this — not ancestor-of-spec — is the reachable case: an ancestor-of-spec branch never becomes an `Orphan` at all, `orphans.go:55-57` and `:181-190`; stated so nobody builds the dead fixture — F3-4/O3-11); **superseded / landed via another route** → the hint names stale-branch deletion plus the R1 adopt path by its full invocation; **stale-deletion shape** → the hint names inspection first (a concrete `git diff` command included) and states plainly that merging would delete landed work; **normal unmerged orphan** → the hint remains exactly `mindspec complete <bead>`, unchanged — the converging common case, safe by construction once R4 preflights the merge it triggers; **evidence unavailable/error** → inspection-first, never the merge (S3-9's leg).
(c) **Sweep scoping** (O3-9): `StaleOpenBead` (`stale_open.go:67`) and `FinalizeOrphan` (`finalize_orphans.go:92`) hints are **out** of the derivation change — the former is correct (reconcile convergence, `complete.go:867-875`), the latter already state-derived — and both are registered in R5's convention with those rationales.
*Falsified if*: any consumer emits a merge-shaped hint for an ancestor/superseded/stale-deletion branch; the derivation is callable without an evidence result; an orphan-hint emitter exists outside the enumeration; executing a printed hint verbatim in any AC-3 fixture removes landed content; the common-case hint changes.

### R3 — Approve-surface refusals are gated by verified facts

(a) **Branch-missing preflight in `impl approve`** (the #218 step-1 wedge): branch existence is resolved as a preflight fact before any merge-base or other git plumbing touches the branch name; a missing spec branch produces a refusal naming the absent branch, the external-merge likelihood, and the R1 adopt path by its full invocation. No raw `exit status 128`, and no wrapped `*exec.ExitError` escapes to the operator (O2-8's positive form).
(b) **Branch-present-but-stale**: `impl approve`'s finalize merge is guarded by R4's preflight (the spec→main producer), so a recreated/stale spec branch refuses before mutation instead of merging the stale snapshot (F3-1's fixture).
(c) **Plan re-approve closed-child provenance** (C2-2 — the live instance): the closed case at `plan.go:820-825` emits `bd delete <id> --force` **only when durable state positively establishes partial/interrupted provenance** (the mechanics — e.g. absence of a bead branch, absence of landed-merge evidence, supersede-run markers — are plan-level; the direction is pinned: deletion requires positive provenance). When evidence indicates completed work, **or is ambiguous or unavailable**, the refusal preserves the record and names inspection/reconciliation instead. The model is the sibling site `plan.go:715-728`, whose deletion hint carries by-construction provenance. `bd delete … --force` joins R5's destructive classifier, so an evidence-free deletion hint anywhere becomes convention-red; both plan.go sites route through the constructor (or a registered rationale) to stay green.
*Falsified if*: a missing branch still surfaces a merge-base error; a stale recreated spec branch reaches the finalize merge unguarded; a closed child with completed-work or ambiguous evidence still draws a `bd delete --force` hint; an evidence-free deletion hint passes the convention test.

### R4 — One work-destruction preflight, every merge producer

(a) A single mandatory preflight API evaluates the shared predicate **before any lifecycle merge mutation**, consulted by all three producers: `CompleteBead`'s bead→spec merge (`mindspec_executor.go:411`), `FinalizeEpic`'s bead→spec auto-merge (`:703`), and the direct spec→main merge (`:916`). A chokepoint anti-drift test enumerates every `gitutil.MergeInto`/`MergeBranch` call site in the lifecycle/executor packages and asserts each consults the preflight, so a new raw producer cannot bypass it (C2-1's required form).
(b) A refusal happens **before mutation** (observables pinned in AC-7), names the evidence, and offers the audited override `--allow-net-deletion "<reason>"`, recorded like `--allow-doc-skew` on epic metadata **and registered in the escape-hatch friction registry** — `cmd/mindspec/selfemit.go`'s `escapeHatchFlags` and `internal/redact`'s `EscapeHatchTokens` — so repeated overrides are visible to friction reporting, not just to per-epic inspection (O3-10). Block + audited override is the gate's unanimous OQ-1 ruling: an autonomous agent pastes what the tool prints and scrolls past warnings, so warn-only makes the tool's output the destructive keystroke.
(c) **Evidence errors refuse fail-closed and retryable**, override available (F3-3; the `:640-659` precedent).
(d) **The common path is untouched**: an ordinary bead merge's behaviour is byte-identical to the pre-change baseline (AC-8's leg i).
*Falsified if*: any producer merges the #218 shape without refusal/override; an override lands without both the metadata record and the journal friction admission; an evidence error falls through to the merge; the ordinary-merge baseline changes; a `MergeInto`/`MergeBranch` call site exists outside the preflight enumeration.

### R5 — The destructive-guidance convention, enforced

The ADR-0035 amendment's red mechanism (F3-2, C2-1, C2-3):
(a) **Classifier**: `internal/guard`'s destructive-command classification expands from the single Req-19 entry to the destructive class — at minimum `git merge`, `git reset`, `git restore`, `git clean -f`, `git branch -D`, `git push --force*`, `rm -rf`, and `bd delete … --force` (the plan may extend the family; it may not shrink this floor). The existing `IsBannedRecoveryCommand`/`FormatFailure` panic behaviour for raw `bd update --metadata` is preserved unchanged.
(b) **Constructor**: destructive-class recovery lines are produced only via an evidence-carrying constructor in `internal/guard` whose destructive variants require a non-defaultable evidence value. Non-destructive recovery lines (including `mindspec complete`, which R4 makes safe upstream) are untouched — the convention targets raw destructive commands, contextually, because a syntactic ban cannot express this class.
(c) **Convention test**: the Req-21 pattern (`recovery_convention_test.go`) is extended contextually: it walks every guard-failure constructor *and the shipped-guidance artifact fixtures*, and any destructive-class command appearing in a recovery line that is neither constructor-derived nor a **registered allowlist entry with an in-code rationale** is red at development time. The test demonstrates its own teeth: a test-injected static merge hint is caught (AC-9's red-on-introduction leg).
(d) **Allowlist, seeded then burned down**: bead 2 seeds the allowlist with every existing site from the Background inventory; later beads convert or re-register them; AC-9 pins the **final** contents exactly — the two executor conflict-recovery lines (`:1688`, `:1721`; rationale: they render only after an R4-preflighted merge attempt conflicted and was auto-aborted, so evidence was consulted upstream — deliberate 092/125 design), and any plan.go/release.go entries that route via rationale rather than constructor. An entry without a rationale, or a leftover seed entry, is red.
(e) **Shipped-guidance sweep**: `.claude/agents/spec-orchestrator.md:163-175`'s raw bypass block (stash / raw merge / `worktree remove --force` / `branch -D` / raw `bd update --metadata`) is removed and replaced with lifecycle-honest guidance; `release.go:257`'s pasteable recovery no longer embeds the `--force` discard — the safe action (commit and re-run) is the recovery line, and the destructive discard is a separately-stated, explicitly-labeled operator choice visible to the classifier.
(f) The ADR-0035 amendment is a **named deliverable with its own pinning test** (O3-13; `adr0041_amendment_test.go` precedent) asserting the amendment names the constructor, classifier, convention test, and allowlist as its enforcement.
*Falsified if*: a newly added static destructive recovery string stays green; the final allowlist contains an unregistered, rationale-free, or leftover entry; the agent template retains the bypass block; release's pasteable recovery still contains the `--force` discard; the amendment lands without its pinning test.

### R6 — Regression evidence, CI-hermetic

The full bd-less `go test -short ./...` lane is **GREEN on `main` at `09f62bd9`** (48 packages, exit 0 — gate-verified by S3-2 in an isolated clone with bd off PATH, orchestrator-re-verified). No cross-package cmd-layer lifecycle table is required by this spec (that deliverable moved to spec 128 together with its seam prerequisites).
*Falsified if*: any fixed class lacks a red-on-revert test; a new gating test skips in the bd-less lane; an AC's stated mechanism is substituted by a stub that fabricates the value the AC then asserts.

## Non-Goals
