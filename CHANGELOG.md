# Changelog

All notable changes to MindSpec are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **Panel disposition ledgers are local** — `mindspec init` removes the former ledger ignore exceptions. Completion and implementation approval read the working ledger without committing it or requiring a ledger commit. Already-tracked files stay tracked; users own any commits of those changes.

### Fixed
- **Panel dispatch diagnostics and briefs** — verify errors retain their message, slot setup failures report a reason without using a reviewer retry, and prompt and launch refuse unfinished briefs. `panel create --brief-file <absolute-path>` copies a filled brief; the panel workflow requires its path as `brief_file`.

## [0.18.0] - 2026-10-22

Two specs and one fix PR since v0.17.0. The theme is **the binary runs the panel and finishes the landing**. PR #271 moves panel execution into the binary: reviewers submit verdicts through `mindspec panel submit`, the binary launches and recovers reviewer processes, and runners, lenses and acceptance questions are config. PR #270 makes the lifecycle verbs finish safely after a partial failure: `impl approve` refuses early for failures it can predict and converges on a re-run, `complete --merge-only` lets you verify a merge before you close the bead, and bead titles no longer decide lineage. PR #269 tells subagents to skip the session-start steps. Not a pure drop-in. Read **Changed** and **Removed** before you upgrade: every new panel round needs submitted v2 verdicts, every reviewer family needs a runner, `panel.substitution` and `merge_strategy` are gone, a bead needs a parent-child edge to its epic, and `spec create` refuses new lettered spec IDs.

On upgrade: add a `panel.runners` entry for each reviewer family that is not the harness (example under **Changed**). Replace `panel.substitution` with `on_quota` on the process runner. Run `mindspec init` to add the ignore lines for `.mindspec/config.local.yaml` and the panel isolation root (`.mindspec-scratch` by default). Remove `merge_strategy` from `.mindspec/config.yaml` (PR #270). Run `mindspec doctor`, and run the printed `bd update <bead> --parent <epic>` for each bead that it lists as title-only lineage (PR #270). After the first v2 panel round in a repo, use only v0.18.0 or later binaries there: an older binary refuses the new ledger records.

### Added
- **`mindspec panel submit` (PR #271, GH #249)** — validates a verdict against schema v2 and binds its bytes to a ledger record. `--file -` reads stdin. `mindspec panel schema` prints the JSON Schema.
- **`mindspec panel launch <slug> <slot>` and `panel recover <slug> <slot> --reason R` (PR #271)** — `launch` runs a process reviewer, retries a refused verdict and submits the result. `recover` submits the recorded output of an orphaned attempt. `--replace` starts a replacement for a final verdict.
- **`mindspec panel checkout` and `panel prompt` (PR #271)** — `checkout --slot S` or `--all` makes an isolated clone and scratch directory for each slot under the isolation root. `--dispatch` records a new harness attempt. `--fixer` makes fixer scratch. `--prune` removes the panel's slot directories. `prompt --slot S` prints the slot review prompt and writes no files.
- **Slot status on `panel verify` (PR #271)** — each slot gets one status: `final`, `damaged`, `void`, `draft`, `running`, `quota_wall`, `launch_failed`, `malformed`, `unsubmitted` or `missing`. `--json` gives the same data with the effective family, model, lens and kind.
- **Panel config (PR #271, GH #229)** — `panel.runners` (`harness` or `process`, with `argv`, `prompt`, `output`, `probe`, `quota_signals` and `on_quota`), `panel.lenses`, `panel.gates.<gate>.lenses`, `panel.gates.<gate>.acceptance` and `panel.isolation_root`. A one-family panel is valid. `mindspec config resolve --gate <gate> [--json]` previews a new roster and the source of each value.
- **Machine-local config (PR #271)** — `.mindspec/config.local.yaml` holds machine-local `panel.runners` and `models`. It merges after the project file. Do not track it. A symlinked local config is refused.
- **`mindspec rules` (PR #271, GH #253)** — lists the panel and bead-loop conduct rules. `--scope` selects orchestrator, implementer, reviewer or fixer rules. `rules show <id>` prints one rule. `instruct` renders the same table.
- **New doctor checks (PR #271, GH #254)** — `doctor` checks each reviewer family's runner, each process runner's command on PATH, the ignore lines for local config and the isolation root, staged-rule markers in installed skills, and stale slot checkouts. `--probe` runs runner probes from any config source with a 10-second limit. `--ci` skips launchers, probes, tool suggestions and stale checkouts. A new `[INFO]` result does not fail `doctor`.
- **`mindspec complete <bead> --merge-only` (PR #270, GH #250)** — runs every `complete` gate and merges the bead into the spec branch, but keeps the bead open. It prints the merge SHA and both parents. Verify the merge, then run `mindspec complete <bead>` until it exits 0 to close the bead. A bead has at most one naming merge: put a later fix in a follow-up bead, and do not revert a `--merge-only` merge by hand. The refusals print the follow-up and restore recovery lines. On a conflict, run `mindspec complete <bead> --merge-only --resolve-merge`.
- **Work in history without a naming merge (PR #270, GH #251)** — when no merge names a prerequisite bead but its commits are in the spec history, `mindspec reattest` reports `ancestor-without-naming-merge` if a content check proves the changes are present. It writes no landed binding. A person must verify the work. The output gives one `mindspec next <dependent> --allow-not-ready=MF-3 --evidence <file>` line for each open dependent. `doctor` reports the prerequisite at Warn.
- **`impl approve` state line and re-run (PR #270, GH #244)** — a failure after the epic close prints one state line ("epic closed" or "epic still open") and the finalize stage that failed. A re-run continues from that stage. After the host deletes a merged spec branch, a re-run prints "already landed" and exits 0 only when the epic, the finalize tip and every landed bead are ancestors of the target.

### Changed
- **Verdict schema v2 for every new round (PR #271)** — every new panel round uses verdict schema v2 with no opt-out. A verdict file without a submission no longer counts. Reviewers use `mindspec panel submit` or the process output channel in their prompt. The latest submission replaces earlier submissions for a slot and round. The ledger retains all submissions. Rounds created before this release keep their old rules.
- **Unreadable verdict files block (PR #271)** — on a v2 round, an unreadable verdict file (FIFO, symlink, directory or oversize), also off the roster, is INVALID in `tally` and blocks the gate. `verify` shows the slot as `damaged`.
- **Runners are config (PR #271)** — zero config runs every slot on the harness. No tool runner ships. Configure process runners in `panel.runners`. A reviewer family needs a runner. `panel create` refuses a family with no runner. Add a runner as shown below.
- **Quota substitution moves to the runner (PR #271)** — `panel.substitution` is retired. Set `on_quota` on a process runner to select its quota substitute. A non-zero exit or a timeout must match a configured `quota_signals` entry before substitution occurs.
- **`panel verify` exit codes (PR #271)** — `panel verify` exits 0 when all slots are final. It exits 1 for running or missing slots, harness drafts, or a pending quota handoff. It exits 2 in every other case, a damaged panel included. Exit 0 does not mean that the gate passes. Scripts that expected exit 0 on a damaged panel must change.
- **Default approval lenses (PR #271)** — spec and plan approval use these default lenses: falsifiability, scope-honesty, contradiction and feasibility.
- **Carried slots at the first v2 round (PR #271)** — at the first v2 round, a carried slot without a family needs a runner that matches its old model. If none exists, create a fresh roster with `mindspec panel create <slug> --round <N+1> --reviewers <n>`.
- **Model-only reviewers (PR #271)** — a model-only reviewer entry runs on the harness with its model. `config resolve` and `doctor` warn for each such entry.
- **Newer ledger records (PR #271)** — a binary older than this release refuses panel ledgers that contain the new record kinds.
- **Thin panel skills (PR #271)** — `ms-panel-run`, `ms-panel-tally` and the `ms-panel` workflow now only dispatch and call the binary. The workflow takes its runners from config. Existing installs refresh through skill snapshots.
- **Shell-safe recovery lines (PR #271)** — recovery lines quote slug and spec arguments for the shell and escape unsafe characters.
- **Session-start steps are for the top-level session (PR #269)** — the generated agent instructions (Claude, Codex and Copilot managed blocks, and the bootstrap templates) now say that `mindspec instruct` and the `bd` steps are for the top-level session only. A subagent that works from a dispatch brief skips them.
- **One has-remote decision in `impl approve` (PR #270)** — `impl approve` decides one time, before any change, whether to push (a remote exists) or merge locally. Finalize uses that value. If git cannot tell whether a remote is configured, approval refuses with `cannot tell whether a git remote is configured` and `recovery: git remote -v`. Before, the error read as "no remote".
- **`impl approve` refuses early (PR #270, GH #244)** — before the epic close, approval runs the merge-layout guard, the work-destruction preflight and, on the push path, a `git push --dry-run`. Only a failed probe refuses. A failed export or artifact commit stops approval before publication and cleanup, and a merged bead worktree with uncommitted work refuses with a recovery line. Before, approval could continue and remove the work.
- **Cleanup keeps hook output (PR #270)** — `complete` and `impl approve` check the bead and spec worktrees again after commit and push hooks run, before they remove a worktree. New user changes stop cleanup, and the file, worktree and branch remain. Tool artifacts such as `.beads/issues.jsonl` stay exempt, but only by exact name and only when both ends of a rename are artifacts.
- **Stale-open with a valid merge is Info (PR #270, GH #250)** — `doctor` reports an open bead that has a valid naming merge at Info, with `recovery: mindspec complete <bead>`. Without a valid merge it stays at Error. An open bead whose merge was reverted is an Error with the restore recovery.
- **Reviewed-tree corroboration (PR #270, GH #233)** — a reviewed SHA now confirms a landed merge when it is an ancestor of the merge's second parent and the difference holds only tool-written files. It never vetoes a landing.
- **Lineage is the parent-child edge only (PR #270)** — a bead's lineage is its one parent-child dependency on an epic. A `blocks` edge to an epic is not lineage. The bead-title fallback is gone. More than one parent epic refuses with `recovery: bd dep remove <bead> <epic>`. `doctor` warns for each open bead that resolved only by its title.
- **Full spec IDs (PR #270)** — `spec approve` writes the full spec ID to the epic's `spec_id` metadata. A lettered spec ID such as `042b-x` resolves to its own spec, never to the base number. When the epic's sources disagree, resolution refuses with `recovery: bd update <epic> --set-metadata spec_id=<id>`. `doctor` reports two epics that resolve to one spec.
- **`spec create` refuses new lettered IDs (PR #270)** — a new spec ID must use digits before the slug. Existing lettered spec directories stay valid.
- **`complete` refuses an unresolved spec binding (PR #270)** — when `complete` cannot resolve the bead's spec, it refuses before any change.

```yaml
# before: create now refuses this entry
reviewers: [{family: codex, model: m1}]
# after
runners: [{family: codex, kind: process, argv: [codex, "{prompt_file}"], prompt: file, output: stdout}]
reviewers: [{family: codex, model: m1}]
```

Place these entries under `panel` in `.mindspec/config.yaml`.
Use `.mindspec/config.local.yaml` for machine-local runners and models.
Runners merge by family: a later entry replaces the same family or appends a new family.

### Removed
- **`merge_strategy` (PR #270)** — the config key had no effect. `impl approve` pushes when a git remote exists and merges locally otherwise. A config that still has the key loads. `doctor` prints `merge_strategy is no longer used; remove it from .mindspec/config.yaml` at Info. `config show` no longer prints the row.
- **`panel.substitution` and `claude_sub_on_quota` (PR #271)** — use `on_quota` on a runner.

### Fixed
- **Ownership at the landing tree (PR #270, GH #234)** — `complete` reads `OWNERSHIP.yaml` from the tree that will land, not from the bead tip. A domain claim made on the spec branch after the bead forked now counts, so `adr-divergence-unowned` no longer blocks an owned path. When `OWNERSHIP.yaml` itself conflicts, plain `complete` refuses before the close with `recovery: mindspec complete <bead> --merge-only`.
- **Half-done `impl approve` (PR #270, GH #244)** — a failure after the epic close no longer leaves a state that a re-run cannot finish. On protected main, a re-run reuses the existing `chore/finalize-<id>` branch.
- **Renamed files cannot hide user changes (PR #270)** — status and diff reads that feed the tool-artifact exemption turn rename detection off and keep exact filenames. A user file renamed onto an artifact path, or named like one with trailing whitespace, now blocks the close.
- **Reattest and finalize text (PR #270)** — reattest and finalize messages no longer print internal record numbers or bead IDs.
- **`spec approve` with a lettered spec ID (PR #270)** — it now writes the epic and its `spec_id`.

## [0.17.0] - 2026-10-21

One spec and two fix PRs since v0.16.0. The theme is **panel integrity**: spec 130 makes the review-panel gate decide only on facts that the binary writes. A panel passes when every finding is fixed, refuted or deferred; the APPROVE count is no longer a decision input. New verbs record refutations, deferrals, rebinds and abandonment, so no skill tells an agent to edit `panel.json` by hand. Staleness compares the reviewed files, not the whole commit. Not a pure drop-in: six behaviour changes are deliberate — the N−1 approve threshold is replaced by the pass rule, default panel sizes are set per gate (bead panels are now 4), `panel create` refuses rounds and bead registrations it used to accept, a hand-edited `panel.json` blocks the gate, `complete` and `impl approve` enforce disposition coverage, and each panel's `dispositions.jsonl` is tracked in git again — see **Changed**. Panels created before this release (no roster in the ledger) keep their old counting and are exempt from the new hand-edit and coverage checks. PR #266 fixes three `mindspec complete` defects, and PR #267 removes internal project references from everything MindSpec installs or prints.

### Added
- **`mindspec panel refute <slug>` (spec 130)** — records an evidenced refutation of one latest-round finding (`--finding ccr[i]`), or of a whole slot when `--finding` is omitted. It needs `--slot`, `--round`, `--ground` (`disproven`, `not-load-bearing` or `out_of_acceptance_scope`, the last with `--ac AC-n` that exists in the spec), `--reason`, `--evidence` (a commit, a repo path or an `https://` URL that resolves) and `--by`. The refutation is pinned to the finding's text: if a reviewer changes the text, the finding is unresolved again.
- **`mindspec panel defer <slug>` (spec 130)** — records that a finding moves to an open follow-up bead (`--bead B --by WHO`). At write time it checks through bd that the bead is open, is not under the spec's epic, has a `discovered-from` edge to the epic or the panel's bead, and has the finding text in its description. `complete` and `impl approve` run these checks again; a closed or changed follow-up bead voids the deferral and blocks the gate with a recovery line. It refuses on a spec-approve panel and on an adhoc panel.
- **`mindspec panel rebind <slug> --reason "<who>: <why>"` (spec 130)** — moves a panel to the live tip with no new round when the panel passes apart from staleness and the new commits need no new review. It refuses a failing panel, a tip that does not descend from the reviewed SHA, and a range that changes `.mindspec/config.yaml`. It records the changed paths, and the old SHA still counts as reviewed for landing checks.
- **`mindspec panel abandon <slug> --reason T --by WHO` (spec 130)** — the audited way to abandon a panel. A later `panel create` revives it and keeps the abandon history.
- **`--reviewers N` on `panel create` (spec 130)** — sets the slot count for one panel (at least 2). Each panel records a roster of slot ids (`R1`…`Rn`) with model and lens; verdict files use the slot id as prefix, and a re-panel copies the previous round's roster.
- **One rule line on `tally`, `verify` and instruct panel state (spec 130, GH #243)** — `rule: PASS iff fresh · intact · all <n> slots in · 0 REJECT · 0 hard_block · 0 INVALID · 0 unresolved REQUEST_CHANGES (fix/refute/defer) — now: …`. No surface prints a threshold. `tally` and `verify` also print the resolved panel directory and round.
- **Prior-round asks and BRIEF archive (spec 130, GH #247)** — on a round bump, `panel create` keeps the old brief as `BRIEF-round-<N>.md` and fills a machine-owned prior-round region from `consolidated-round-<N-1>.md`.
- **Durable reviewed SHA on landing (spec 130, GH #233)** — when the panel gate allows a bead merge, `complete` writes the reviewed SHA and the panel id (`<slug>@r<N>`) to the bead's landed binding, so the record survives finalize.

### Changed
- **Pass rule replaces the N−1 threshold (spec 130)** — a panel passes only when it is fresh and intact, every roster slot has a latest-round verdict, and it has 0 REJECT, 0 `hard_block`, 0 INVALID and 0 unresolved REQUEST_CHANGES. A REQUEST_CHANGES is resolved when each of its findings is refuted or has an effective deferral. A panel with no APPROVE verdicts can pass; one with five APPROVEs and one unresolved REQUEST_CHANGES blocks. Any number of refutations can resolve a panel (previously two refuted findings blocked with nothing left to fix). `approve_threshold` in config or `panel.json` still parses but has no effect, and surfaces print `approve_threshold <value> ignored (legacy; not decision-bearing)`.
- **Default panel size is set per gate (spec 130)** — with no `panel.reviewers` list, spec, plan, final and adhoc panels have 6 slots and bead panels have 4, split round-robin between Claude and Codex. An explicit `panel.reviewers` or `panel.gates.<gate>.reviewers` list still wins. Config load refuses a panel of fewer than 2 reviewers, with the message "a one-reviewer panel cannot pass".
- **Staleness compares the reviewed files, not the commit (spec 130, GH #235, #228)** — `panel create` records a subject digest. Spec and plan panels cover the spec directory; bead, final and adhoc panels cover the whole tree. Review directories and `.beads/issues.jsonl` are excluded, so a commit that touches only those no longer makes a panel stale. Panels with no recorded digest keep the old whole-commit check.
- **`panel create` refuses unsafe registrations (spec 130, GH #238, #242)** — it refuses a round below the latest, and the latest round when it already has verdicts (previously this moved the reviewed SHA under the old verdicts). It refuses an unreadable `panel.json` instead of overwriting it, and carries refutations, deferrals and rebinds forward on a round bump instead of dropping them. `--gate bead` needs a `bead/<id>` target, and the bead id comes from it; `--bead` with another target or another gate refuses. A slug that matches panels in more than one spec refuses unless `--spec` selects one, so another spec's panel can no longer answer a tally.
- **Only the panel verbs write `panel.json` (spec 130)** — `create`, `rebind`, `refute`, `defer` and `abandon` write each change to the panel's `dispositions.jsonl` ledger first, then rewrite `panel.json`. The gate blocks with `panel.json changed outside the panel verbs` when the two disagree. `panel disposition append` refuses the verb-owned record kinds and agent-written coverage manifests. `ms-panel-run` and `ms-panel-tally` now name the verbs; existing installs refresh through skill snapshots.
- **`complete` and `impl approve` enforce disposition coverage (spec 130)** — `tally` writes the coverage manifest when every pass condition except freshness holds. After the panel gate allows a merge, `complete` checks that the latest round's manifest matches the roster and verdicts and that every finding has a disposition; `impl approve` runs the same check on every non-abandoned panel of the spec, final review included. A missing manifest names `mindspec panel tally <slug> --spec <S>`. `MINDSPEC_SKIP_PANEL` and `enforcement.panel_gate: false` skip it as they skip the gate.
- **Panel ledgers are tracked in git again (spec 130)** — `mindspec init` adds `!.mindspec/specs/*/reviews/*/` and `!.mindspec/specs/*/reviews/*/dispositions.jsonl` after the review-directory ignore lines, so `dispositions.jsonl` survives finalize; briefs, verdicts and `panel.json` stay ignored. After a bead merge, `complete` commits the bead panel's ledger as `chore(panel): ledger` on the spec branch. `complete` refuses when git ignores the ledger, and `impl approve` refuses when a ledger has uncommitted changes; both print the recovery commands. Existing repos run `mindspec init` to add the two lines.
- **Unexpected verdict files count for nothing (spec 130)** — a verdict file whose slot is not on the roster is named by `tally` and is not counted, except that a REJECT, `hard_block` or INVALID in it still blocks.
- **The `ms-panel` workflow refreshes on upgrade (PR #267)** — setup now replaces an unmodified `.claude/workflows/ms-panel.js` with the new version, as it does for skills. A user-modified file is left in place with a notice.
- **No internal project references on the installed surface (PR #267)** — skills, CLI help, setup files, `reattest` output and recovery lines no longer cite MindSpec's own design records, spec numbers, requirement ids or bead ids. A test guards the installed surface. Release binaries are built with `-trimpath`, and a maintainer-only migration helper with machine-local paths is no longer compiled into the binary.

### Fixed
- **`complete --resolve-merge` can commit on `main` (PR #266)** — the pre-commit hook refused the merge commit, so a conflicted bead merge could not finish. The bypass applies to that one commit only. Before it commits, `complete` checks the files that had conflicts and refuses when a conflict marker is still present.
- **No empty `Next bead ready:` line (PR #266)** — when no bead is ready, `complete` prints a neutral line instead of the label with nothing after it.
- **Correct worktree after `complete` (PR #266)** — the post-complete hint no longer points at another agent's worktree.
- **A bead panel with no bead id no longer passes `complete` (spec 130, GH #242)** — previously `complete` found no panel and allowed the merge.
- **A one-slot panel no longer blocks forever (spec 130, GH #237)** — panels need at least 2 slots, and a registration with fewer is a Block whose recovery is a re-create with `--reviewers 2`. Panel subcommands no longer print cobra usage on every Block.
- **Adhoc tally recovery is runnable (spec 130)** — it no longer prints `--spec` for an adhoc panel, and it prints the recorded spec id instead of `<id>`.

## [0.16.0] - 2026-10-19

One spec since v0.15.0. The theme is **readiness and tracker honesty**: spec 129 makes the verbs that decide what work is ready tell the truth about the tracker and about git. `mindspec next --spec` selects by plan-bead lineage and names every bead it does not select, no decision-bearing bd read can be silently truncated, a claim always lands in its lineage spec, MF-3 finds and names an off-first-parent landing instead of denying it exists, and a readiness override is scoped to named signals and backed by evidence. Not a pure drop-in: six behaviour changes are deliberate — `--allow-not-ready` is now a scoped value flag that needs `--evidence` (the bare flag refuses), `bead ready-check` no longer honours legacy or malformed override markers, `next` claims only plan beads (`<epic>.<N>`) and refuses a scope that disagrees with the bead's lineage spec, `next --spec` membership no longer depends on `bd ready --parent` or the title, stale panel registrations no longer contradict a landed merge, and `mindspec init` gitignores review directories — see **Changed**. Otherwise well-formed repos behave as v0.15.0. Deferred to follow-on specs rather than shipped here: the OWNERSHIP.yaml wrong-ref read (GH #234), `impl approve` closing the epic before finalizing (GH #244), and the merge-to-close verification window (GH #250) go to the readiness part-2 spec; #233's review-to-landing binding and the rest of GH #251 go to spec 130. Review retention after finalize is undecided and nothing ships for it.

### Added
- **Near-miss reporting on `mindspec next --spec` (spec 129, GH #255)** — every bd-ready bead linked to the spec that is not selectable (by plan-bead ID form, `parent`, title, or `metadata.spec_id`) is printed by ID with its true reason and one recovery line: no lineage (reparent with `bd update <id> --parent <epic>`), a non-epic parent, lineage resolved to another epic by title number or by an epic dependency, a follow-up child that `plan.md` does not map, or a non-plan bead. Near-misses never change selection and are printed whether the selectable set is empty or not; the blocking classes make an otherwise-empty result exit non-zero, and informational ones never change the exit code. Exclusion notices now name bead IDs instead of a count.
- **Derived state on an empty `next --spec` result (spec 129, GH #255)** — when no plan bead is selectable and no selector was given, `next` prints the lifecycle-children tally, `stored phase: <p>; child-derived phase: <q>`, the sentence "an empty ready set is not evidence the spec is complete; the derived phase above is", and one recovery keyed on the tally (`impl approve`, worktree recovery for an in-progress bead, `bd blocked --parent <epic>`, or `plan approve`), plus `repair phase` when the derived phase is ahead. A failed child read is an indeterminate refusal, never an empty tally.
- **Audited off-first-parent acceptance in `mindspec reattest` (spec 129, GH #239)** — when the first-parent scan finds no owned candidate, `reattest` nominates through a reachable-merge fallback (`git log --merges --topo-order`) that admits only source-named `Merge bead/<id>`, `Merge branch 'bead/<id>' into <spec-branch>` and `Merge bead/<id> into <spec-branch>` subjects. It accepts only after four git-derived checks — exactly one candidate (two or more refuse as `multiple-fallback-candidates`), no contradicting surviving bead tip, no revert at the current tip, and read errors as errors — and writes the binding plus an audited tuple (`mindspec_landed_reattest_merge_sha`, `_second_parent`, `_scanned_branch`) with a fallback provenance string in one metadata write. A re-run is a no-op only when the stored audit is valid and matches both binding and candidate. Panel registrations outside the tip's history print as `advisory:` lines and never refuse.
- **Override evidence and validated markers (spec 129)** — a scoped override that records a failing signal requires `--evidence <path>`, a readable regular file of 1 byte to 64 KiB read before any mutation; the marker (schema v2) stores the overridden signals, a sha256 fingerprint of each signal's complete failure set, a timestamp, and the evidence path, sha256 and size, never the evidence text. `mindspec bead ready-check` reads the marker back and treats a failing signal as covered only when the marker is valid and every current failure was fingerprinted: growth uncovers, shrinkage stays covered. It exits 0 only when every signal passes or every failure is covered, and otherwise names the uncovered signals with `mindspec release` / re-claim recovery lines. `ms-bead-impl`'s prose coverage rule is replaced by "run `mindspec bead ready-check <id>`; proceed on exit 0", and pre-129 skill snapshots let existing installs refresh.
- **ADR-0045 accepted (spec 129)** — "The binary owns sequence and rules; skills are harness adapters" lands, amending ADR-0040 §1 and ADR-0044 with back-pointers. Its status note records that only the override-coverage rule has moved so far.

### Changed
- **`mindspec next --spec` selects plan beads by lineage (spec 129, GH #255)** — the scoped set is one uncapped global `bd ready`, with a member being a non-epic open bead of form `<epic>.<N>` whose lineage (`phase.FindEpicForBead`, unchanged) is the spec's epic and whose `N` `plan.md` maps (both a `## Bead` heading and a `work_chunks` entry). It no longer depends on how a bd version reads `--parent`, nor on the title containing the full spec ID, so a detached or short-tagged plan bead is selected. `plan.md` is read from the committed `spec/<id>` blob when present, with a one-line notice when the checkout's copy differs; a lineage or plan read error refuses rather than dropping a row. Positional IDs and `--pick` that cannot be honoured refuse instead of being ignored (`no ready plan bead for spec <S>; positional <id> cannot be claimed from an empty ready set`, `--pick <N> is out of range: 0 items`, `bead <id> is bd-ready but is not linked to spec <S>`). The multi-spec menu prints `mindspec next --spec=<spec-id>`.
- **Claim lineage guard and dispatch into the lineage spec (spec 129; ADR-0041 amended)** — before any mutation, `next` refuses a bead that is not a plan bead of its lineage spec, refuses when `--spec` or the resolved target spec disagrees with the lineage spec, and refuses when `spec/<lineage>` does not exist. The claim is dispatched into the lineage spec, so a bead branch is cut from `spec/<id>`, never from `HEAD`. A reparented non-dotted bug or a `<other>.<N>` bead with a tagged title, previously claimable, now refuses with `bd show <id> --json`.
- **`--allow-not-ready=<signals>` is signal-scoped (spec 129)** — the flag takes a comma-separated subset of `MF-1`…`MF-4` and proceeds only when every currently failing signal is named; a named-but-passing signal prints a note and records nothing, and a failure that could not be evaluated is never overridable. The bare flag (including `--allow-not-ready MF-3`) refuses before positional resolution, and `=all` is not accepted. Every override records a fresh marker that replaces the previous one; an existing marker never authorizes a claim. Recovery strings, flag help, USAGE, the workflow-state machine and the domain docs use the scoped form.
- **Legacy and malformed override markers are no longer honoured (spec 129)** — `ready-check` reports `override marker is legacy (no evidence) — not honoured` for a pre-129 `{signals, overridden}` marker and `override marker is malformed — not honoured` for anything else that is not schema v2, and exits non-zero for the uncovered signals. A bead claimed under an old marker needs `mindspec release` and a scoped, evidenced re-claim.
- **MF-3 tells the truth (spec 129, GH #239, #232)** — a closed dependency is held to the landed-merge test only when it belongs to the bead's lineage spec by a tracker fact (plan-bead form, `metadata.spec_id`, or parent edge; never the title); other closed dependencies pass as "landed-merge test not applicable", and a membership read error fails rather than passing. The first-parent scan stays primary; when it finds nothing, a reachable landing is found and NAMED ("reachable from <spec-branch>'s tip but off its first-parent chain") with `mindspec reattest <D>` as the only acceptance path — the automatic read never passes it unless a valid audited tuple from `reattest` matches it and the git checks pass again at read time. Only a genuine zero-candidate result says no landing exists; contradiction and revert get their own messages. MF-3 now evaluates every dependency, and every signal reports all its failures with one recovery line chosen by precedence. #232 is closed on its real mechanism (a stale panel SHA vetoing a correct corroboration). `complete`'s merged-unclosed reconcile, `stale_open`, orphan hints, plan approve and adopt stay first-parent only.
- **Stale panel registrations are advisory (spec 129, GH #232)** — in `FindLandedMerge` and `reattest`, the panel leg is the set of every well-formed `reviewed_head_sha` for the bead: it confirms only when it contains the exact second parent, and a non-matching set is non-corroborating instead of contradicting. Empty, placeholder and malformed values are skipped and never reach git. A surviving-tip or binding contradiction still contradicts, and a non-matching set alone still never closes a bead.
- **Untruncated bd reads (spec 129)** — every decision-bearing `bd ready` / `bd list` call goes through one waist that passes `-n 0`; any other `-n` / `--limit` value is rejected without spawning bd. If `bd ready` still announces `Showing N of M`, the read is an error, never a silent short read (including `complete`'s post-close ready lookup, which now reports indeterminate mode). A row-cap lint keeps new call sites on the waist.
- **MF-2 form symmetry (spec 129)** — bead text and spec text are tokenized from one shared form table: appended and parenthetical sub-letters (`R9a`, `R9(a)`), Roman parentheticals degrading to base, bare base, and hyphenless `AC9` normalized to `AC-9` on both sides, so a claim resolves whichever side uses which form. Exactness is preserved: `R9(b)` still dangles against a spec with only `R9(a)`.
- **Review directories gitignored on `init` (spec 129)** — `mindspec init` adds `.mindspec/specs/*/reviews/**` and `.mindspec/reviews/**` to `.gitignore` (idempotent), so panel reviews stay local by default. Already-tracked review files stay tracked and their edits are still committed: `CommitPaths` now stages tracked paths with `git add -u` and untracked paths with ordinary ignore checks, never force-adding an ignored file. Every review consumer reads the filesystem, so gates work on untracked reviews. `setup` does not add the entries; existing repos that want the default add the two lines themselves.

### Fixed
- **A detached or short-tagged plan bead no longer disappears from `next --spec` (spec 129, GH #255)** — the reported shape (a ready plan bead with no parent edge that `ready-check` evaluated but `next` dropped) is selected, and every other linked bead is named rather than silently excluded.
- **Off-first-parent landings no longer read as "no merge exists" (spec 129, GH #239)** — MF-3 previously reported a correctly named bead merge that reached the spec tip off its first-parent chain as unlanded; it now names the merge and the audited recovery.

## [0.15.0] - 2026-10-18

Two specs since v0.14.0. The theme is **lifecycle-verb trustworthiness**: spec 127 stops the verbs from printing or executing recovery that destroys work and gives an externally-merged spec a first-class, audited, merge-free path to its terminal state; spec 128 makes the verbs tell the truth about state (modes, result-before-guidance, hints that don't make state worse) and act deterministically on it (`complete` retry convergence, a proportional claim guard, honest bead selection). Not a pure drop-in: four behaviour changes are deliberate — a one-time per-epic phase-semantics v2 migration, `plan approve` now storing `plan` instead of `implement`, `complete`'s doc-sync / ADR-divergence gates measuring a prospective snapshot before committing (ADR-0041 §1 amended), and the dirty-tree block on `mindspec next` replaced by a proportional claim guard (ADR-0025 amended) — see **Changed**. Otherwise well-formed repos behave as v0.14.0, and an ordinary bead merge is unchanged. Deferred to follow-on specs rather than shipped here: MF-3 readiness false-negatives (GH #239, #232, #234), `impl approve` closing the epic before pushing (GH #244), the remaining spec-completion-signal face of GH #255, and the panel-artifact-integrity and `reattest` clusters.

### Added
- **`mindspec impl adopt <spec-id> --reason "<why>"` (spec 127, GH #218)** — an audited, merge-free terminal path for a `review`-state spec whose content reached `main` outside the lifecycle (for example an external PR with the spec branch deleted). It requires positive landed evidence (the remote spec-branch ref, corroborated by a fresh fetch, covering the epic), closes the epic, writes the finalize export, and records an audit marker (reason, identity, timestamp); it performs no spec-to-main merge, and the resulting done-state matches a normal `impl approve`. `--attest-unverified` is an explicit escape for the no-source / negative / evidence-error states and records that landing was NOT verified and was operator-attested.
- **Work-destruction preflight on every lifecycle merge (spec 127)** — `complete`'s bead-to-spec merge, `impl approve`'s bead auto-merge, and the spec-to-main merge consult one shared predicate before mutating and refuse a merge that would delete landed work (the superseded / stale-deletion shape behind #218). Evidence errors fail closed and retryably; an already-landed ancestor proceeds as a no-op. The audited override is `--allow-net-deletion "<reason>"` on `complete` and `impl approve`, recorded on epic metadata and registered in the escape-hatch friction registry.
- **`--resolve-merge` on `complete` and `impl approve` (spec 127)** — conflict recovery re-enters a preflighted product surface instead of printing a raw `git merge` line: a preserved merge conflict is never aborted, and `--resolve-merge` re-prints the resolution steps or completes the merge once the index is resolved and staged.
- **Destructive-guidance convention (spec 127)** — lifecycle diagnostics emit a destructive-class command only through an evidence-carrying constructor, and a repo-wide convention scan (Go sources, shipped skills, agent guidance, and the `internal/setup` guidance literals) turns a newly introduced static match of the reviewed destructive-command floor red. The floor is a finite reviewed set, not closure — a novel destructive family is caught by review, not the scan. ADR-0035 is amended to record the contract, and the shipped `spec-orchestrator` guidance no longer teaches raw merge / branch-delete / `bd update --metadata` bypasses.
- **`mindspec repair phase --force-backward "<reason>"` (spec 128, GH #248)** — `repair phase` refuses any write that moves the epic backward in lifecycle order (`spec < plan < implement < review < done`) unless forced with a recorded reason, which the result line names. Every `mindspec_phase` writer is serialized under one repo-scoped advisory lock, so a concurrent verb's newer phase is never overwritten by a stale repair.
- **Honest draft mode (spec 128, GH #220)** — a spec with a spec directory and branch but no epic reports mode `spec`, never `idle` alongside a non-empty `activeSpec`. This is a narrow ADR-0023 amendment scoping "all lifecycle discovery goes through beads" to post-approval lifecycle; from `spec approve` onward beads remain the sole authority.
- **Per-verb agreement table (spec 128)** — each lifecycle verb's post-state mode, as reported by `state show`, the instruct tail, and the status-aware derivation, is documented (ADR-0023, `lifecycle-modes.md`) and pinned by row fixtures.
- **Frozen-contract guidance (spec 128, GH #221)** — idle- and review-mode guidance and `merge-safety.md` state that implementing a previously frozen or externally-merged contract still requires a new spec, and name `mindspec impl adopt <spec-id> --reason "<why>"` as the exit for the externally-merged predecessor.

### Changed
- **One-time phase-semantics v2 migration (spec 128)** — stored `mindspec_phase` now means what ADR-0023 derives: `plan` until the first lifecycle claim. `EnsurePhaseSemanticsV2` reconciles legacy epics once, idempotently and under the phase lock, keyed on a durable `mindspec_phase_semantics: "v2"` epic-metadata marker. A legacy never-claimed epic (stored `implement`, all lifecycle children open) is rewritten to `plan`; any other state gets the marker only, with its phase untouched. It runs ahead of the preflights of `impl approve`, `plan approve`, `complete`, `next`'s claim, `release`, and `repair phase`; until it has run, `state show` emits a legacy notice instead of the old mismatch warning. No operator action is required.
- **`plan approve` stores `plan`; the first claim advances it to `implement` (spec 128, GH #248)** — previously `plan approve` wrote `implement` while ADR-0023 derives `plan` for an unclaimed epic, so the stored-vs-derived warning fired and recommended a `repair phase` that rewrote a correct state. Stored and derived now agree in that window, and after `release` returns an epic to all-open. Anything that reads the stored value right after `plan approve` now sees `plan`. `release` is the one unforced backward writer, through a single sanctioned sync.
- **`complete`'s gates measure a prospective snapshot before committing (spec 128, GH #186; ADR-0041 §1 amended)** — the doc-sync and ADR-divergence gates run before `complete`'s own materialization commits, over a snapshot of the bead worktree's prospective content (tracked, untracked, and deletions), and the commit is then built from exactly the measured tree. This deliberately reverses ADR-0041 §1's validate-the-committed-tip design; ADR-0037 is not amended. A gate-refused `complete` now leaves no commit authored by the tool, so an immediate retry (with the original gate's override, for example `--allow-doc-skew`) meets the same gate instead of a stale-SHA panel block manufactured by the tool's own tracker auto-commit.
- **Proportional claim guard on `mindspec next` (spec 128, GH #179; ADR-0025 amended)** — the dirty-tree block is removed for the worktree-creating claim, which is the only claim mode. The paths a claim writes in the invoking checkout are a derived, test-pinned list (today the gitignored `session.json` and the already-exempt `.beads/issues.jsonl`), so unrelated uncommitted work no longer blocks a claim; a future claim-written tracked path re-arms the block. The guard still never advises stashing or discarding a human's work.
- **Result before guidance; guidance for the actual mode (spec 128, GH #245)** — every durable-state verb prints what changed before any instruct tail, and the tail renders the verb's real post-state (`spec create` shows spec guidance, not `idle`). When state cannot be derived, the tail and `complete`'s summary say "cannot determine mode: <reason>" instead of presenting an idle or fabricated `plan` mode. The literal #245 zero-result-lines shape is unreachable at this release (fixed earlier by spec 092's `completeTail` extraction) and is now pinned by tests.
- **Deterministic, honest bead selection (spec 128, GH #187, #146)** — a positional bead ID resolves to exactly that bead or errors with the true reason; `--pick N` is honored on `--emit-only` and indexes the same ordered set as the claim path (`bd ready`'s priority order, preserved end to end), with `--pick 0` meaning unset and negative values rejected. With several ready beads and no pick, `next` defaults to displayed row 1 and says so. Every spec-filter exclusion is reported with a count and reason, and a non-empty ready set that filters to empty is a loud error rather than "No ready work found." An explicit `--spec` that fails to resolve now refuses instead of silently widening to a global `bd ready`.
- **`spec approve` replay is non-regressing (spec 128)** — re-running it against an existing epic backfills `plan` only when no phase is stored, leaves a later phase untouched, and says which of backfill or no-op happened.

### Fixed
- **`impl approve` on a missing spec branch no longer surfaces a raw `exit status 128` (spec 127, GH #218)** — it refuses naming the absent branch and the adopt path; an indeterminate existence probe is a distinct retryable refusal that never routes to adopt; a present-but-stale recreated branch is refused before the finalize merge.
- **Orphan recovery hints are state-derived (spec 127, GH #218)** — the four orphan-hint consumers (`complete`, `impl approve`, `doctor`, adopt's refusal) render from one derivation: ancestor-of-main and superseded branches draw branch deletion plus the adopt path, a stale-deletion shape draws inspection first and says merging would delete landed work, and `mindspec complete <bead>` remains the hint only for a normal unmerged orphan. `doctor --fix` runs `complete` only in that normal case.
- **Plan re-approve no longer hints `bd delete --force` on a closed child unconditionally (spec 127)** — deletion is hinted only when durable state positively establishes partial or interrupted provenance; completed, ambiguous, or unavailable evidence preserves the record and names inspection.
- **The stored-vs-derived phase warning no longer recommends a self-worsening recovery (spec 128, GH #248)** — on the plan-approve → first-claim and `release` routes the warning does not fire; where it remains reachable (out-of-band `bd` edits) a forward disagreement keeps `repair phase` and a backward one names `bd show <epic-id>`.
- **bd failures behind `next` surface bd's own stderr (spec 128, GH #146)** — the stale-binary / schema-drift class is diagnosable from mindspec's output; stderr is bounded and passed through terminal-safe escaping.
- **`mindspec state show` never exits 0 with an empty mode (spec 128, GH #220)** — a lifecycle-discovery failure (bd unavailable, Dolt unreachable) is a non-zero ADR-0035 refusal naming the failure, and one derivation is authoritative for mode.

## [0.12.0] - 2026-07-18

Repairs the mutating lifecycle verbs — `mindspec complete`, `mindspec impl approve`, and `mindspec plan approve` — under one invariant: **gate-before-mutate**. Every immutable gate fact (the bead's owning spec from its epic lineage, branch ancestry, epic membership, plan and obligation state) is resolved and every derivable refusal evaluated *before* the first state mutation, so a verb either refuses cleanly up front — with a convergent recovery command — or completes without corrupting the state machine. Recovery is always forward-reconcilable, never rollback. Backward-compatible: absent the new checks, every verb behaves as v0.11.1 on the happy path.

### Fixed
- **`mindspec complete` no longer acts on the wrong spec** (`mindspec-zty3`) — the owning spec is now resolved authoritatively from the bead's parent epic (never from the session cwd or active worktree), and an explicit `--spec` hint that mismatches the lineage is refused in preflight. A transient bd/Dolt lookup error fails closed with a retry command instead of silently falling back to cwd resolution.
- **`mindspec impl approve` no longer merges a different spec's in-progress bead** (`mindspec-blp6`) — epic finalization scopes its bead-branch merge and cleanup to the finalizing spec's own plan-declared lifecycle beads, and fails closed on an enumeration error rather than silently skipping the leg.
- **`mindspec plan approve` now wires bd dependency edges deterministically** (`mindspec-ffm4`, `mindspec-cpqc`) — the emitted plan scaffold carries a `work_chunks` frontmatter block with `depends_on` (so a filled scaffold produces the edges that make `bd ready` / `mindspec next` correct for parallel multi-agent work) plus the per-bead `**Acceptance Criteria**` section the validator requires. Plan approve resolves the epic and child set fail-closed before any mutation, and warns loudly on a missing `work_chunks` block or a failed edge wiring.
- **Tracker auto-commits never target protected `main`** — the artifact self-heal stages an explicit lifecycle pathspec (never `add -A`) and refuses on a main checkout with a named recovery; the `--commit-msg` commit is likewise guarded.
- **`internal/instruct` tests are hermetic** (`mindspec-z4ps`) — the test sandbox no longer escapes to an enclosing real worktree, so the suite passes when run from inside an active-spec worktree.

### Added
- **`mindspec doctor` divergence checks** — a stale-OPEN cross-check (a bead still open in the tracker whose work has landed on the spec branch) and finalize-orphan surfacing (an unmerged `chore/finalize-*` carrier or stale committed tracker state), each reporting a recovery command; the same predicates surface in `mindspec instruct` idle guidance.
- **`mindspec doctor --ci`** — a CI-appropriate mode that runs the repo-integrity / lifecycle-divergence checks while skipping developer-local environment checks (merge driver, hooks, bd version), wired into the build workflow so a real divergence fails CI without false-positiving on a fresh checkout.
- **Advisory per-bead scope surfacing** (`mindspec-jli8`) — a non-fatal warning at `complete` when a bead's changed files fall outside its declared domain, and a plan-lint flagging a single file assigned to two beads.
- **ADR-0041** records the gate-before-mutate (preflight → commit → reconcile) contract, cited from every mutating verb's preflight, with a fault-injection regression suite pinning forward-reconciliation at each mutation point.

### Performance
- **`mindspec doctor` and SessionStart are fast again** — the new lifecycle divergence scans previously iterated every spec directory with uncached `bd` subprocesses (doctor did not complete; idle `instruct` ran on every SessionStart). They now share one epic cache and a single global open-bead query — a fixed two `bd` queries per scan regardless of repository history (`doctor` back to its baseline, idle `instruct` in single-digit seconds).

### Security
- New agent-writable render sinks (the advisory-scope warning, the plan-lint finding, and the doctor/instruct divergence findings) are escaped through `internal/termsafe`, keeping hostile spec-directory or branch names from forging terminal or transcript lines — consistent with the v0.11.0 hardening.

## [0.11.1] - 2026-07-17

A P1 fix for a layout-resolution regression that could wedge a repository flattened after upgrading to v0.11.0.

### Fixed
- **Flattened repos with an ordinary `docs/` no longer wedge into `mixed`** (`mindspec-5x8r`) — layout markers were set by bare directory existence, so a correctly-flattened repo that also kept a normal repo-root `docs/` (or a leftover/empty `.mindspec/docs/`) was classified `layout: mixed` permanently. **One deliberate gate-behavior change:** a panel carrying an unresolved REQUEST_CHANGES no longer passes on the approve count alone (see Changed, Spec 114). Everything else is backward-compatible: absent the new config blocks, every gate and resolver behaves exactly as v0.10.0.

### Security
- **Panel messages can no longer forge terminal or transcript lines** — closed a terminal/prompt-injection hole (`mindspec-fl91`): hostile bytes (NUL, ESC/CSI sequences, embedded newlines forging a `recovery:` line) planted in agent-writable panel artifacts — `panel.json` fields (bead ID, abandon reason, recorded SHA, refutation slots), verdict filenames and verdict strings, the panel directory name, stale-worktree paths, and in-progress-bead commit subjects — previously reached `panel verify`/`panel tally` output, `mindspec complete`'s gate messages, and the SessionStart transcript block verbatim, where a forged line becomes a forged instruction to the orchestrating agent. Every attacker-influenceable field is now escaped at the gate's construction boundary via the new stdlib-only `internal/termsafe` escaper (a single implementation home: printable ASCII passes through unchanged, everything else renders as a single-line quoted literal), with the sibling render sites that bypass the gate message covered too. Clean panels — all-printable-ASCII values, i.e. every real one — render byte-identically, and no gate decision changes. (Spec 116)

### Added
- **Orchestration config substrate (ADR-0040)** — `.mindspec/config.yaml` gains `panel:` (reviewer mix, approve-threshold expression, quota-substitution policy), `models:` (phase→model tiering), and `loop:` (governance skeleton: gate authority, halt conditions, budget, context policy) blocks, plus a top-level `runner:` adapter selector — all parsed, defaulted, validated, and surfaced by the new read-only `mindspec config show` (which quote-escapes any control bytes or embedded newlines in a config-controlled value before it reaches stdout). `panel:` seeds a fresh `panel.json`'s creation-time defaults; the gate's Allow/Block decision stays a pure function of the recorded `panel.json`. `models:`, `loop:`, and `runner:` are declared and validated now; in-binary enforcement is deferred to later specs. (Spec 109)
- **Panel lifecycle verbs: `mindspec panel create | verify | tally`** — the panel lifecycle that lived in skill prose and a hand-typed `panel.json` is now three agent-neutral commands. `create` writes the panel directory, BRIEF stub, and `panel.json` in one operation, stamping the config-resolved reviewer count/threshold and co-bumping `round` with a freshly captured `reviewed_head_sha` by construction (a re-panel can never leave a stale SHA misdirecting reviewers). `verify` prints a read-only completeness/staleness report with the **same** PASS/BLOCK the complete-gate computes; `tally` renders the verdict table and decision from the binary — exit 0 on Allow, non-zero on Block with a recovery line — so `panel.PanelGateDecision` is the single decision home everywhere. The verdict-file/slot schema is documented as the agent-neutral contract other runners target. Additionally, `mindspec spec approve` now validates the spec with the same canonical parsers the downstream gates consume, so a mis-formatted `## Impacted Domains` entry or a dangling ADR-Touchpoint link fails cheaply at spec-approve instead of detonating two gates later. (Spec 110)
- **`/ms-panel` workflow panel runner** — a tracked Claude Code dynamic workflow (`.claude/workflows/ms-panel.js`, embedded in the plugin and installed by `mindspec setup` on the Claude target) runs a full review panel behind the panel verbs: registration via `panel create`, reviewer fan-out per the configured mix (codex reviewers run behind wrapper agents that persist codex's raw stdout as a `.codex.log` audit artifact and write the verdict file themselves), a semantics-preserving parse-retry ladder that can never launder a rendered verdict into a substitute's, deterministic `claude-sub` substitution on a quota wall, and the verify + tally output returned verbatim as one compact result. The workflow is constrained to an explicit command allowlist and never runs `mindspec complete`. Selected by the 109 `runner:` key; the skills-driven launch path remains the default. (Spec 111)
- **Per-gate panel config** — the `panel:` block gains a `gates:` map (`spec_approve`, `plan_approve`, `bead`, `final_review`, `adhoc`) and a generalized reviewer entry `{model, lens, count}` — open model vocabulary (never an enum, so a brand-new model id loads on day one; unknown ids draw a warning, never an error), first-class lenses with a deterministic round-robin default, and legacy `{family, count}` entries still accepted. A model-level `substitution.substitutes` map declares the quota-wall stand-in policy with the slot-id-preserving `reviewer_id` convention. Gate-scoped resolvers feed panel creation, and `mindspec config show --gate <name> [--json]` prints a gate's resolved slots/threshold as a documented, additive-only machine contract. With `gates:` absent, behavior is identical to v0.10.0. (Spec 112)
- **Codex symlink protection in `mindspec setup`** — all managed-doc writes for claude, codex, and copilot now route through one shared `safeio`-backed helper; `mindspec setup codex` refuses to write through a symlinked `AGENTS.md` (previously only claude/copilot were protected), with refusal and per-agent full-content-equality tests. (Spec 107)
- **`AGENTS.md § Bead-loop guardrails (mindspec)`** — the canonical orchestrator fences section that `CLAUDE.md` and the `ms-*` skills reference now exists (the reference was previously dangling). (Spec 107)
- **MIT LICENSE** — the repository now ships a LICENSE file (MIT) at the repo root. (PR #191)
- **Docs** — new autonomy, brownfield-onboarding, and review-panels guides, plus a CONTRIBUTING.md. (PR #172 follow-up)

### Changed
- **The panel gate blocks on any unresolved REQUEST_CHANGES** — a reviewer's REQUEST_CHANGES can no longer be silently out-voted by the approve count: `mindspec complete` now passes only when every latest-round verdict is an APPROVE or an explicitly refuted REQUEST_CHANGES (the approve threshold remains a necessary floor on genuine approvals). The escape is a per-slot **audited refutation** — a `refutations` entry (slot, round, reason, evidence) recorded on `panel.json` — following the abandonment precedent: legitimate precisely because always audited, never silent. An applied refutation always leaves a durable `panel_refuted` audit on bead metadata — across retries, escape hatches, and even a later-removed panel — and never counts toward the approval floor, so refutation cannot buy past a sub-threshold panel. ADR-0037 amended. (Spec 114)
- **`mindspec impl approve` refuses to finalize an unsettled spec** — the one remaining lifecycle verb that could merge a bead branch un-gated now REFUSES (no epic close, no phase write, no merge, no push) when any closed bead under the spec's epic was closed via raw `bd close` without `mindspec complete`, or carries an unsettled durable refutation obligation — naming the bead and, best-effort, the unresolved REQUEST_CHANGES slot(s). Recovery converges on the one gate home: `mindspec complete <bead>`, which tolerates an already-closed bead and re-runs the full layered gate. The gate fails closed on infrastructure errors; a spec whose beads all went through `complete` finalizes exactly as today. (Spec 115)
- **YAML frontmatter is the single source of approval truth** — the `## Approval` prose scan is gone; spec status comes only from the frontmatter `status:` field (case-insensitive). Hand-rolled frontmatter fence scanners across approve/validate/contextpack were consolidated onto the canonical `internal/frontmatter.Parse`; one deliberate tightening: a space-padded `---` fence is now treated as no-frontmatter everywhere. (Spec 108)
- **Validation gates are cheaper** — `OWNERSHIP.yaml` manifests load once per gate run (was once per changed-file × domain, including per-domain `git show` fan-out at refs); cited ADRs parse at most once per validation run; doctor's dead-manifest check walks the tree once per check (was once per domain). All proven behavior-identical by golden-diagnostics and seam-count tests. (Spec 108)
- **`internal/trace/**` and `.golangci.yml` are now workflow-owned** — claimed in OWNERSHIP.yaml; the dead `trace.Event.MarshalJSON` no-op marshaler was removed (NDJSON output golden-proven identical) and three stale lint carve-outs referencing deleted code were dropped. (Spec 108)
- **`mindspec complete` is cheaper** — the children query is a single comma-joined `bd list --parent` call via the new exported `phase.FetchChildren` (was one call per status, ~5), and the immutable spec→epic lookup is resolved once per run (was four throwaway lookups); the post-close children read stays fresh. (Spec 107)
- **Dead-code sweep (−271 lines)** — ~25 confirmed-dead functions/clusters removed across `internal/{hook,gitutil,layout,doctor,validate,contextpack, next,recording,harness,panel}`, `cmd/mindspec`, and `plugins/mindspec` (verified unreachable even from tests via `deadcode -test`), including the no-op `SetUsageTemplate` in `cmd/mindspec/hook.go` and the dead flags on the deprecated `state set`; the hidden `spec-init` alias now reuses `spec create`'s `RunE` instead of a byte-identical copy. (Spec 107)

### Fixed
- **Panel-verb & workflow follow-up wave** — `panel verify`/`panel tally` now tell the truth about a **non-bead** panel's staleness: a spec-approve or final-review panel previously always reported PASS-advisory (it could never Block, even with zero verdicts or a REJECT on file) and rendered a malformed `bead/` message fragment; staleness now resolves from the panel's own recorded target, through the same unchanged decision function. Also in the wave: the `ms-panel.js` shell-safety regex rejects a bare `$` (closing `$HOME`-style variable-expansion survival in workflow inputs); `panel create` gains `--gate <name>`, stamping the recorded gate identity and that gate's per-gate creation-time defaults (the writer side spec 112 deferred); and the empty-string-model config ambiguity is reconciled (resolves to the family) and pinned by test. (Spec 113)
- **Protected-main `impl approve` finalize** — resolves the v0.10.0 Known Issue (`mindspec-wu7t`): on a branch-protected `main`, the finalize flow now lands the beads JSONL sync on a from-main branch when the spec branch is already merged, is retry-idempotent, and orders its pushes, so the committed `.beads/issues.jsonl` can no longer be left out of sync with the source-of-truth Dolt store. (PR #174)
- **`complete` close-verify reads committed state** — the post-close verification now reads bd's committed state (`bd show --as-of HEAD`) instead of the uncommitted working set, so a close that never landed in a Dolt commit can no longer pass verification. (PR #173)
- **Headless spec-grill guard** — the grill auto-chained by `ms-spec-create` no longer stalls a headless/non-interactive run: the skill gains a three-mode disposition (interactive grill; self-answer under an explicit non-interactive instruction; a blocking defer with an audit marker as the backstop). (PR #176)

## [0.10.0] - 2026-06-24

A large release headlined by the **flattened `.mindspec/` layout**, plus ten specs' worth of lifecycle, gate, and CLI work merged since v0.9.0.

**Upgrading is non-breaking:** the binary alone changes nothing on disk — a multi-tier resolver (flat → canonical → legacy) reads every layout, first-exists-wins — and the new lifecycle gates engage only within the mindspec spec workflow (and only once you register a panel), so existing layouts and non-panel usage keep working as before. Flattening an existing project is opt-in via `mindspec migrate layout` (clean tree + no unmerged pre-flatten branch; `--allow-branch`/`--force` scope the precondition; `--abort` rolls back a pre-publish run; forward-only after publish; run `mindspec doctor` afterward to confirm links).

### Added
- **Flattened `.mindspec/` layout** — `specs/`, `adr/`, `domains/`, `core/`, and `context-map.md` are now top-level children of `.mindspec/`; panel reviews are co-located under `<spec-dir>/reviews/`; repo dogfood docs moved to a top-level `project-docs/` tree.
- **`mindspec migrate layout`** — an opt-in transactional mover (two commits per move: a pure `git mv`, then a link-rewrite) with `--abort` pre-publish rollback, forward-only publish, a root-doc 404 link-check, and `--allow-branch`/`--force` precondition escapes.
- **`ms-spec-grill` skill** — an agent skill that interrogates a draft spec one question at a time, grounded in the live domains, ADRs, and code, to drive out vague language, synonym-dodges, non-falsifiable claims, cross-requirement contradictions, and unprobed edge cases; backed by a tracked `bench/grill/` eval and auto-chained by `ms-spec-create`.
- **`mindspec next <bead-id>`** — claim a named bead (full or short-form ID) instead of the first ready item.
- **`mindspec release <bead>`** — cleanly reverse a wrong claim (remove the worktree, then re-open the bead); refuses a dirty worktree without `--force`.
- **`mindspec version`** subcommand, matching `--version` byte-for-byte.
- **`doctor` layout detection**, plus bd schema-drift and multiple-`bd`-on-PATH checks.
- **`spec-orchestrator` agent** (`.claude/agents/`) for multi-bead / multi-spec autonomous runs.
- **`MS_HARNESS_MODEL`** override for the LLM test harness.

### Changed
- **Panel gate enforced inside `mindspec complete`** — the ADR-0037 review-panel gate now runs inside `complete <id>`, keyed off the bead ID, so it covers every invocation form (wrapped, quoted, aliased); the PreToolUse hook remains only as a defense-in-depth backstop. A bead with no registered panel still completes — the gate fails closed only once a panel exists.
- **Ownership/ADR gates resolve domains by file path** — `## Impacted Domains` entries that are file paths now resolve to their owning domain by glob-matching the `OWNERSHIP.yaml` manifests, at one shared source consumed by the bead-time divergence gate and the plan-time coverage/citation gates; a correct manifest is no longer rejected or forced onto `--override-adr`. Zero/multi-owner cases still error clearly.
- **`mindspec spec create`** branches from `origin/<default-branch>` after a fetch (default branch detected, not hardcoded), falling back to local `HEAD` with a warning when offline.
- **`plan approve`** auto-fills a missing `version` to `"1"` instead of hard-blocking (`status`/`spec_id` stay required).
- Claim failures now surface bd's real stderr (so a stale-binary schema error is legible).

### Fixed
- **`complete` close-verify** — after `bd close`, `complete` forces a Dolt commit and verifies the bead persisted as closed; it can no longer print `closed` + exit 0 on a close that didn't land, and keeps the worktree on failure.
- **`bd close` bypass guard** — a lifecycle floor detects and blocks using `bd close` to skip the panel/merge gates, steering callers to `mindspec complete`.
- **Fresh-repo merge safety** — bootstrap provisions the beads JSONL merge driver (portable, cross-worktree) from commit 0.
- **ADR numbering & worktree** — `adr.NextID` parses slugged `ADR-NNNN-slug.md` filenames (no colliding low IDs); `adr create` writes into the invoking worktree.
- **Git argument safety** — `internal/gitutil` rejects hostile `-`-prefixed ref/branch operands at its boundary and fast-fails with `GIT_TERMINAL_PROMPT=0` so a slow/auth-prompting origin can't hang `spec create`.
- **Phase cache** now counts `blocked` and custom-status children, matching the state-advance path.
- **`migrate layout` hardening** — precondition scoping (unrelated stale branches no longer false-block), a wider repo-root 404 link-check, and resume-before-clean-tree-precondition so a crashed run can recover.
- **Harness** — a Sonnet full-suite audit fixed three LLM-test failures and trimmed a slow scenario's turn count.

### Removed
- The `.mindspec/docs/` wrapper directory, the vestigial `glossary.md` and `policies.yml`, and the retired PreToolUse heuristic complete-matcher (now redundant with the in-binary gate) and harness prose path-scraper.

### Governance
- **ADR-0039** (Flat `.mindspec/` Layout v2) — **Accepted**.
- **ADR-0037** (panel gate) amended — in-binary enforcement is authoritative and the review location moved to `<spec-dir>/reviews/`.
- **ADR-0032** (ADR semantic gates) amended — path-like Impacted-Domains entries are normalized to their owning domain rather than rejected.
- **DOCS-LAYOUT.md** updated to the flat layout.

### Known issues
- On a branch-protected `main`, `mindspec impl approve` can momentarily leave the committed `.beads/issues.jsonl` out of sync with the source-of-truth Dolt store, because the lifecycle's finalize commit cannot land directly on protected `main`. A one-time manual `.beads` sync resolves it (the post-merge hook is then idempotent). Tracked as `mindspec-wu7t`. Normal feature work and non-protected repositories are unaffected.
